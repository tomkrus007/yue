# 官方客户端群管理实现分析

> 目标：以官方 macOS 客户端（`yx-packages/yuexiu_1786088172677.dmg`，云上越秀.app，Electron；web 包 `Resources/app/web/html/static/js/home.7717570b45127039f907.js`，压缩未混淆）内的「群管理」（会话内群设置）为基准，说明入口、权限模型、接口契约、操作后的会话/消息行为与本地数据模型，并给出 `YX/` 的缺失项与分阶段落地方案。
>
> 证据来源：应用包内未混淆 web 源码、`web/init.sql`（本地库 schema）、`web/i18n/zh-CN-default.json`（UI 文案）、`yx-cloud-kb/repo/analysis/api/desktop-api-endpoints.txt`（497 个命名端点清单）与 `mobile-server-paths.txt`（APK 字符串池交叉验证）。
>
> 本文只做源码观测，**未对生产环境执行任何写操作**；所有写接口的实际返回与权限校验见第 8 节待验证项。组群的建群流程见 [官方客户端组群实现分析](./官方客户端组群实现分析.md)。

## 1. 范围与总体架构

- 「群管理」= 建群之后的维护：群资料、成员、公告、禁言、禁言白名单、机器人、模板、二维码/邀请码、审批、转让、退群/解散、空间归档。
- 全部是用户中心（UAM）的 **REST** 操作：`{uamApiUri}` + 标准 uamapi 头（`Authorization: Bearer` + `version` / `displayVersion` / `ClientType: pc` / `deviceId` / `X-Requested-With`），与组群建群一致。
- **EMB 长连接不承载任何群管理命令**。改名、加人、退群、解散、转让等结果由服务端以系统消息下发（`Group_Command_*`），客户端只负责渲染文本，不据此修改本地群缓存。
- 与组群的关系：组群 = 创建（`v2/groups/create`），群管理 = 创建之后的全部维护动作；两者共用 `contact-client` 的地址与请求头。
- 群类型与模板：
  - `type`：1 普通、2 讨论组、3 项目群、4 工作群（`ContactDetailView` 现有标签一致）。
  - `templateId` / `templateCode`：`groupDefault`（普通群）、`workGroupDefault`（工作/团队空间）、`meetingGroupDefault`（会议群，不可转让）。
- 配置中心开关控制功能可见性：`IS_ENABLE_GROUP_SILENT`（禁言）、`useGroupRobot`（机器人）、`useGroupTemplate`（群模板）、`useExportGroupUsers`（导出成员）。

## 2. 入口、页面结构与权限

### 2.1 入口

| 入口 | 触发 | 行为 |
|---|---|---|
| 会话/群卡片头部 | 点群信息图标 `icon-right` | 打开群设置抽屉（标题 i18n `Group_Setting` = "群设置"） |
| 群卡片头部二维码 | 点 `icon-qrcode` | 客户端本地生成二维码（`[OpenBuiltIn]\nkey=GroupCard\ngroupId=<id>`），不走接口 |
| 群卡片底部 | 群主显示「转让群组」（`Group_Transer`） | 打开通讯录选择窗（`type:"GroupTransfer"`，标题 `Window_Title_SetOwner` = "转让群组"） |
| 群卡片底部 | 所有人显示「退出群组」；群主文案变成「解散群组」 | `outGroup()` 按 `memberRole` 分流：群主 → 解散，其余 → 退群 |
| 群卡片底部 | 普通群（`templateId == "groupDefault"`）且 `canEdit` | 「升级为工作空间」，属团队空间线，不在本文范围 |
| 群成员区 | 点「群成员」/「+」 | 打开选择窗（`GroupAddUser`）；群成员可移除（`GroupRemoveUser`） |

### 2.2 群设置面板组成（官方组件）

`groupSetting` 内嵌：群信息（`groupInfo`）、群成员（`groupMember`）、群公告（`groupNotice`）、群机器人（`groupRobot`）、群管理（`groupManage`）、群二维码（`groupQRcode`）、空间状态（`spaceStatusModal`，仅工作空间）。禁言、审批开关、允许邀请等开关直接定义在群设置组件内，按配置中心开关与权限显示。

### 2.3 权限模型

| 字段 / 判定 | 含义 |
|---|---|
| `memberRole = -1` | 非群成员（可查看群卡片，不能聊天） |
| `memberRole = 0` | 普通成员 |
| `memberRole = 1` | 管理员（`isAdmin`） |
| `memberRole = 2` | 群主（`isOwner`） |
| `canEdit = memberRole > 0` | 可改群名/介绍/公开设置/加人/移人 |
| `ownerRole = memberRole === 2` | 群主专属：审批开关、群模板、禁言、转让、解散、升级工作空间 |
| `canAddMember = memberRole > 0 \|\| allowInvite` | 普通成员在「允许成员邀请」开启后也能拉人 |
| `canChat = memberRole > -1` | 非成员不能发消息（对应 i18n `Msg_Tip_NoInGroup`） |
| `forbidEditInfo = type === 3` | 项目群禁止编辑群资料 |
| `isMeetingTemplate = templateCode === "meetingGroupDefault"` | 会议群不显示转让 |

## 3. 接口契约

约定：

- 成功判定统一为响应体 `code === 200`；失败取 `message` 弹 toast。官方部分封装（`updateGroup` / `applyJoinGroup` / `allowInviteToGroup`）只判 HTTP 200，复刻时按 `code` 判定更稳。
- 路径中的 `{groupId}` 需 `encodeURIComponent`。
- 「JSON」= `Content-Type: application/json` + `JSON.stringify(body)`；「表单」= `application/x-www-form-urlencoded`；「无 body」= `POST` 且不传内容。

### 3.1 群资料

| 用途 | 请求 | body / query |
|---|---|---|
| 群详情 | `GET /v2/groups/{id}/details` | — |
| 改名 | `POST /v2/groups/{id}/update`（JSON） | `{ name }` |
| 群介绍 | 同上 | `{ notes }` |
| 公开/私密 | 同上 | `{ isPublic: 0 \| 1 }` |
| 入群确认开关 | 同上 | `{ joinMode: "0" \| "1" }` |
| 允许成员邀请 | 同上 | `{ isAllowMemInvite: true \| false }` |
| 移除关联服务号 | 同上 | `{ relatedAccountId: "" }` |
| 群模板列表 | `GET /v1/grouptemplate/list` | —（客户端再插入伪项 `defaultGroupTemplate`「普通模板」） |
| 设置模板 | `POST /v1/groups/{id}/template/set?templateId=` | 无 body |
| 取消模板 | `POST /v1/groups/{id}/template/cancel` | 无 body |
| 空间归档 | `POST /v1/groups/{id}/archive`、`/archive/cancel` | 工作空间专用，不在普通群管理范围 |

`updateGroup` 的官方封装是一个「按字段局部更新」的通用方法：`updateGroupInfo(groupId, field, value)` 内拼 `{ [field]: value }` 后 POST。群设置页的改名、介绍失焦即保存；开关类直接调 `setGroupType`（`isPublic`）、`setJoinModeType`（`joinMode`）、`setAllowInvite`（`isAllowMemInvite`）。

群详情返回一个群对象，官方本地 `groups` 表缓存字段与之对应（`name` / `notes` / `memberRole` / `isPublic` / `joinMode` / `type` / `templateId` / `msgReceiveType` / `ownerId` / `memberCount` / `relatedAccountId` / `silentStatus` / `bulletinCount` 等），另有内存态 `extendParams`（JSON 字符串，含 `tag` 等）、`windows`（群卡片页签，缺省为「群公告 / 群成员」）、`subjectId`、`groupJieSan`。

### 3.2 成员管理

| 用途 | 请求 | body / query |
|---|---|---|
| 成员分页 | `GET /v2/groups/{id}/users/page` | `groupId`、`offset`、`limit=500`、`isCount=true`、`includeRole` |
| 成员（旧版） | `GET /v1/groups/{id}/members`、`GET /v1/groups/{id}/users/page` | 同上（`YX` 现用 v1 members） |
| 加成员 | `POST /v2/groups/{id}/members`（JSON） | `{ users: [{ id, memRole: 0 }] }` |
| 移成员 | `POST /v2/groups/{id}/members/delete`（JSON） | `{ users: [{ id }] }` |
| 重置管理员 | `POST /v2/groups/{id}/admin/reset`（JSON） | `{ users: [{ id }, ...] }`（**整份覆盖**：传入所有应保留的管理员，群主不列入） |
| 群内昵称 | `POST /v2/groups/{id}/members/nickname`（JSON） | `{ nickName }` |
| 转让群主 | `POST /v2/groups/{id}/transfer`（JSON） | `{ userId }` |
| 退群 | `POST /v2/groups/{id}/quit` | 无 body |
| 解散 | `POST /v2/groups/{id}/dismiss` | 无 body（仅群主；官方按 `memberRole` 自动分流到 quit） |
| 申请入群 | `POST /v2/groups/{id}/apply`（JSON） | `{ content, joinCode? }` |
| 邀请入群 | `POST /v2/groups/{id}/members/apply`（JSON） | `{ content, userIds: [...] }` |
| 审批入群 | `POST /v2/groups/{id}/approve`（JSON） | `{ userIds: [...], result: true }` |
| 邀请/申请确认 | `POST /v2/groups/{id}/invite/respond` | 端点清单存在，`home.js` 中未观察到调用（推断为旧版入口） |

要点：

- 成员角色 `memberRole` 与建群 body 的 `memRole` 同义：0 普通、1 管理员、2 群主；本地 `group_members` 表同名字段。
- 管理员不是逐个增删，而是 `admin/reset` 覆盖：官方把「已是管理员 + 本次勾选」或「已是管理员 - 本次取消」的完整数组提交。
- 移出成员、退群、解散、转让都带二次确认（`Group_Tip_ConfirmDelMember` / `Group_Tip_ConfirmOutGroup` / `Group_Tip_ConfirmDelGroup`）。
- 加成员成功后官方会 `getMyGroups()` 刷新本地群缓存；退群/解散成功回调只关闭卡片，不主动删本地会话（见第 4 节）。

### 3.3 禁言

| 用途 | 请求 | body |
|---|---|---|
| 开启全员禁言 | `POST /v1/groups/{id}/silent` | 无 body |
| 解除全员禁言 | `POST /v1/groups/{id}/silent/cancel` | 无 body |
| 禁言名单 | `GET /v1/groups/{id}/silent/members` | — |
| 新增禁言名单 | `POST /v1/groups/{id}/silent/members`（JSON） | `{ memberIds: [...], silentTimeType }` |
| 移除禁言名单 | `POST /v1/groups/{id}/silent/members/remove`（JSON） | `{ memberIds: [...] }` |
| 白名单（不受限发言） | `GET/POST /v1/groups/{id}/unsilent/members`、`POST .../remove` | 新增/移除均 `{ memberIds: [...] }` |

- 名单项含 `silentExpireIn` / `silentExpireTime`（毫秒时间戳），客户端据此显示「还有 X 天解除」。
- 全员禁言受配置中心 `IS_ENABLE_GROUP_SILENT` 控制；开启后仅群主、管理员与白名单成员可发言（i18n `MuteModeTips`、`MuteingCanNotSendMsg`）。
- `silentTimeType` 的具体枚举源码未展开（推断为分钟/小时档位数值），见第 8 节。

### 3.4 群公告

| 用途 | 请求 | 参数 |
|---|---|---|
| 列表 | `POST /v1/groups/{id}/bulletins`（表单） | `groupId`、`limit=10`、`cursor`（**是 POST + 表单，不是 GET**） |
| 创建 | `POST /v1/groups/{id}/bulletins/create`（JSON） | `{ isImportant, title, content, resources }` |
| 更新 | `POST /v1/groups/{id}/bulletins/update?bulletinId={bulletinId}&isSendMessage={0\|1}`（JSON） | 同上 |
| 删除 | `POST /v1/groups/{id}/bulletins/delete`（表单） | `bulletinId` |
| 详情 | `GET /v1/groups/bulletin/{bulletinId}` | — |
| 设为重要 / 取消 | `POST /v1/groups/{id}/bulletins/important`、`.../unimportant`（表单） | `bulletinId` |

- 列表返回 `{ data, total, cursor }`，游标分页；`cursor` 为空表示到底（推断，官方以回调参数 `e` 直接透传给分页组件）。
- 更新接口的 `isSendMessage=1` 表示同时向群里发一条公告消息。
- 本地 `bulletin` 表只缓存 `bulletinId / groupId / isRead / brief`；`groups` 表用 `bulletinCount`、`bulletinId`、`showBulletinList` 生成群卡片的公告角标。

### 3.5 邀请码、入群与群列表

| 用途 | 请求 | 参数 |
|---|---|---|
| 生成入群码 | `POST /v1/groups/joincode`（表单） | `{ groupId, isOverride: false }` → `data.code`（4 位数字）+ `data.expireDate` |
| 用码查群 | `GET /v1/groups/joincode/{joincode}` | — |
| 我的群分页 | `GET /v2/groups/page` | 分页参数 |
| 公开群 | `GET /v1/groups/public` | —（客户端按名称/拼音本地过滤，并标记 `isAlreadyIn`） |
| 部门群 | `POST /v1/groups/org/group/count`、`POST /v1/groups/org/group/list` | `{ orgId }` / 列表参数 |
| 我加入的群 | `GET /v1/groups/joined`（`YX` 已用） | — |

- 「设置入群密码」就是生成 4 位 `joinCode` 并展示二维码/数字；`isOverride: false` 表示已有码不复用而是新建（官方在本地列表为空时才生成）。
- 群二维码是客户端本地生成，内容为纯文本 `[OpenBuiltIn]\nkey=GroupCard\ngroupId=<id>`，扫码方再走「按 joinCode/群 id 入群」流程，**没有二维码接口**。

### 3.6 群机器人（P2，不在首批范围）

端点：`GET /v1/groups/{id}/robots`、`GET /v1/groups/robot/sources`、`GET /v1/groups/robot?robotId=`、`GET /v1/groups/robot/detail?robotId=`、`POST /v1/groups/robot`、`POST /v1/groups/robot/modify`、`POST /v1/groups/robot/delete?robotId=`、`POST /v1/groups/robot/webhooklink?robotId=`。受 `useGroupRobot` 开关控制；消息推送依赖机器人 webhook，复刻优先级低。

## 4. 操作后的会话与消息行为

- **系统消息**：改名（`Group_Command_ReNameByYou` / `...ByOther`）、加人（`AddIn` / `AddDirect` / `InviteIn`）、退群（`Out`）、被移出（`KickOutByYou` / `KickOutByAdmin`）、解散（`Del`）、转让（`Transer`）、入群（`JoinIn` / `InviteGetIn` / `PswJoinIn`）全部是服务端下发的普通消息，客户端只渲染，不改会话列表。
- **本端主动操作后**：
  - 改名/介绍/开关：只刷新群详情；群名变化要同步更新本地会话名（`sessions[].name`），否则会话列表仍是旧名。
  - 加/移成员：刷新成员列表；官方加载成功后调 `getMyGroups()` 回写本地 `groups`。
  - 退群/解散：官方只关闭群卡片（`cardClose`），**不删除本地 `message_session`**；会话是否消失取决于后续 `emb/sessions/latest` 与本地列表刷新。复刻建议显式处理：解散/退群成功后从会话列表移除或标记不可发送。
  - 转让群主：本端 `memberRole` 由 2 变 1，需要重新拉群详情刷新权限，否则按钮仍显示「解散群组」。
  - 审批/邀请：只刷新成员与申请列表，不产生本端系统消息（由服务端另行下发）。
- **非成员**（`memberRole = -1`）仍可打开群卡片看公告/成员，但发送消息会被服务端拒绝（`Msg_Tip_NoInGroup`）。

## 5. 本地数据模型（`web/init.sql`）

关键表与用途：

- `groups`：群卡片缓存。含 `groupId, name, notes, type, memberRole, memberCount, isPublic, joinMode, msgReceiveType, ownerId, relatedAccountId, silentStatus, templateId, bulletinCount, bulletinId, bulletinShowType, showBulletinList, extendParams(内存), lastUpdatedDateOnServer`。
- `group_members`：`groupId, userId, memberRole, nickName, silentStatus, status, isDeleted, name, namePinYin`；`memberRole` 0/1/2。
- `group_apply`：入群申请（`applyId, applyName, groupName, groupId, content, results, isReceiver, createTime`），`results` 注释：0 接受 / 1 已接受 / 2 已过期 / 3 已撤销 / 4 重复添加。
- `group_add`：邀请/加人通知（`targetId, targetName, content, results`）。
- `group_Transfers`：群转让/模板转换提示（`targetId, targetName, content, actionText, action, scope, templateCode, isShowTip`）。
- `bulletin`：`bulletinId, groupId, isRead, brief`，用于群公告未读角标。

读取策略（官方）：`getGroupCardInfo` 先请求 `v2/groups/{id}/details`，失败回退 `getGroupFromLocal`（本地 `groups` 表），并给 `windows` 补默认项「群公告 / 群成员」。复刻无本地 SQLite，可用内存缓存 + 通讯录群列表（`im.groups`）替代。

## 7. 落地方案

### 7.1 分层与文件

1. **服务层**：新增 `src/services/group-client.ts`（或继续放 `contact-client.ts`，群管理接口较多，建议独立）。
   - 复用 `ContactService` 的 `base` / `headers()` / `unwrapCode` 逻辑（可抽 `uamRequest()` 私有工具）。
   - 统一返回 `code === 200` 判定，失败抛 `message`；写接口不自动重试，避免重复建群/重复转让。
   - 首批方法：`getGroupDetail`、`updateGroup(id, patch)`、`getGroupMembersPage(id, offset)`、`addMembers`、`removeMembers`、`resetAdmins`、`setMyNickname`、`transferOwner`、`quitGroup`、`dismissGroup`、`listAnnouncements`、`createAnnouncement`、`updateAnnouncement`、`deleteAnnouncement`、`setMuteAll`、`listMutedMembers`、`setMutedMembers`、`removeMutedMembers`、`applyJoin`、`inviteMembers`、`approveMembers`。

3. **UI**：

   - 转让成功后重新拉群详情刷新 `memberRole`。

### 7.2 分阶段

| 阶段 | 内容 | 理由 |
|---|---|---|
| P0 | 群设置页骨架 + 群资料（改名/介绍/公开/入群确认/允许邀请）+ 成员列表 + 加人/移人 + 退群/解散 | 覆盖日常最高频操作，写接口最少 |
| P1 | 转让、管理员、群内昵称、审批入群、邀请入群、邀请码/二维码、全员禁言与名单 | 依赖成员列表与权限刷新，需真机联调 |
| P2 | 群公告、群模板、机器人、空间归档/升级工作空间 | 公告是独立子模块；模板/机器人/空间属扩展，且部分走团队空间线 |

### 7.3 边界

- 群公告的富文本编辑可先只支持纯文本 + 重要标记，`resources`（附件）结构待验证。
- 群机器人、工作空间、会议模板、空间状态（`v1/groups/{id}/status`、`v1/space/*`）不在群管理首批范围。
- 群二维码不生成图片文件，按官方格式输出可复制的 `[OpenBuiltIn]` 文本即可（如需图形，用现有前端二维码库自行渲染）。

## 8. 待验证项（生产写操作，需用户明确要求后用真实账号执行）

9. 验证姿势：用测试账号建群 → 改名/改介绍 → 加一个小号 → 设管理员 → 发公告 → 开全员禁言 → 转让 → 小号退群 → 群主解散，全程观察对端与会话列表。避免在真实业务群上操作。
