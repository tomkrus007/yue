# 腾讯会议 P0 验证记录

对应分支：`spike/wemeet-p0`
产出代码：`YX/src-tauri/wemeet/`、`YX/src-tauri/src/wemeet.rs`、`YX/src/views/WemeetView.vue`

> **状态（2026-11）**：P0 通过。生产账号实测可以正常拉起腾讯会议会前窗口，
> `v1/tencent/meeting/config` 对 YX 放行；P1 最小闭环（会议页 + 发起/入会 + 生命周期）已实现。

P0 只回答两个问题：

1. 官方 `TMSDK.framework` 能否在 Tauri（非 Electron）进程里初始化？
2. `v1/tencent/meeting/config` 是否对非官方客户端放行？

第 1 个问题先用最小 `.app` 壳跑通（见第 1 节），随后由真实账号在 YX 内确认；
第 2 个问题同样由真实账号确认放行（见第 2 节）。

## 1. 已完成验证（不需要账号）

用一个最小 `.app`（只含 `Info.plist` + 链接 TMSDK 的可执行文件 + 软链到 `vendor/TMSDK.framework`）
直接调用与本项目完全相同的那份 `wemeet_shim.cc`，结果：

| 调用 | 结果 | 说明 |
| --- | --- | --- |
| `GetWemeetSDKInstance()` | 非空 | C++ 接口可用，不需要 Electron |
| `Initialize(假 sdk_id/sdk_token)` | 回调 `OnSDKInitializeResult code=0 "init success"` | **假 token 也能初始化成功**，初始化不校验凭据 |
| `Login("https://example.invalid/probe")` | 回调 `OnLogin code=-1008 "invalid login param"` | 登录回调链路正常，失败不崩溃 |
| `ShowPreMeetingView`（未登录） | 回调 `OnActionResult code=-1006 "user unauthorized"` | 未授权时不弹窗但也不崩溃，符合预期 |
| `IsInitialized()` | `1` | 状态查询正常 |
| 进程退出前 `Uninitialize` + `ReleaseWemeetSDKInstance` | 正常退出 | 无残留 |

框架启动时会通过 `NSTask` 拉起 `TMSDKHelper.app`（日志 `app did start`、`Startup result: 0`），
说明独立 helper 进程在 Tauri 场景下同样可用。

### 关键结论：必须跑在 `.app` 里

同一个可执行文件，**裸二进制**（`target/debug/YX`，即 `pnpm tauri dev` 的形态）调用
`Initialize` 会在 `NSTask SdkTimeReport:...start sdk` 之后立刻 `SIGSEGV`；
放进带 `CFBundleIdentifier` 的 `.app` 后恢复正常。

- 原因：SDK 通过 `NSBundle` 定位容器/资源目录，裸进程拿到的是 `Containers/(null)`。
- 因此 P0 联调**只能用** `pnpm tauri build --debug` 生成并运行 `YX.app`，不能用 `pnpm tauri dev`。
- `wemeet_init` 已加前置检查：不在 `.app` 内直接返回可读错误，避免整个应用崩溃。

## 2. 真实账号验证（已完成）

用生产账号在 `YX.app` 里走「会议 → 连接并打开会前界面」：

| 项目 | 结果 |
| --- | --- |
| `GET {rtcUri}v1/tencent/meeting/config` 是否校验客户端 | **放行**，能拿到 sdkKey/sdkToken/ssoUrlPrefix/idToken |
| `Initialize` | `OnSDKInitializeResult code=0` |
| `Login(ssoUrlPrefix + idToken)` | 成功 |
| 会前窗口 | **正常弹出**（腾讯原生窗口） |

### 复现步骤

1. `./scripts/sync-wemeet.sh`（把 355 MB 框架拷到 `src-tauri/vendor/`，不入库）
2. `pnpm tauri build --debug`
3. 打开 `YX/src-tauri/target/debug/bundle/macos/YX.app`，用生产账号登录
4. 左侧导航「会议」→「连接并打开会前界面」
5. 若失败，展开页面底部「连接状态 → 原生事件」，按 `code/msg/service` 定位

## 5. P2 已完成：IM 会议联动

- 收到 `msg_type 15`（VIDEOCHAT）的腾讯会议邀请时，会话里渲染成会议卡片
  （标题 + 会议号 + 「加入会议」按钮），点击直接入会；实时邀请还会弹一次全局
  「加入会议」窗口（`components/MeetingInvitePrompt.vue`，离线补发/会议中不弹）
- 兼容官方「分享到聊天」发出的 `msg_type 99 / type 3` 卡片（按钮动作 `[JoinWeMeet]`）
- 卡片指令新增 `[JoinWeMeet]`（按会议号入会）、`[StartWeMeet]`（打开会前界面）、
  `[OpenApp] appCode=linkMeeting & supplier=tencent`（入会），
  不再落到「应用 linkMeeting 未提供可打开的电脑端地址」
- 聊天顶部「视频会议」：单聊直接邀请对方，群/部门会话先选人。
  流程与官方 `joinWeMeetCallback` 一致——先快速会议，等 `OnJoinMeeting` 回调带回会议号，
  再逐个发送邀请：先 `msg_type 15`（触发对方弹窗），紧接着 `msg_type 99` 会议卡片
  （聊天里的可回看入口，官方客户端收到 15 不渲染，只靠这张卡片留记录）
- 会议页新增「邀请同事」并显示当前会议号（来自 `OnJoinMeeting` 的 `param`）
- 两条邀请消息格式都与官方逐字一致（15 的 `[OpenApp]` + `appCode=linkMeeting` +
  `supplier=tencent` + `meetingCode` + `title`；99 的 `display_type 0/1/4` + `[JoinWeMeet]` 按钮）
- 收到官方邀请时对方会同时发 15 和 99，时间线按「同发送人 + 同会议号 + 10 分钟内」把
  配套的 99 卡片去重，避免出现两张一样的会议卡片；单独的「分享到聊天」卡片照常显示

## 6. P3 已完成：多账号缓存与响铃邀请

- 会议缓存目录改为按账号隔离：`{app_cache_dir}/{Uid}/wemeet_cache`，与官方
  `cacheDataPath + Uid + "/wemeet_cache"` 一致（`Uid` 只保留字母数字和 `-`/`_`）
- 退出登录时 `stop(true)`：先 `ReleaseWemeetSDK`，再删当前账号的缓存目录，
  对齐官方 `cleanWeMeetCache`；直接退出应用不删，避免拖慢退出
- 响铃邀请：登录成功后调用 `EnableRingInvitationView`，由 SDK 自绘接听窗口；
  会议页「连接状态」新增开关（localStorage 持久化，默认开）。关掉后只能通过
  IM 邀请入会。`OnRingInvitationEvent` 仍会进事件面板，便于排查
- 未接 `HandleRingInvitation`：只在关闭 SDK 原生接听窗、自己做接听 UI 时才需要，
  当前用原生窗口，接听/拒绝/超时都交给 SDK

**为什么官方没有响铃**：反查官方 `home.js` 只处理了 `OnInviteMeeting`（点击邀请后
弹出会议详情窗，再选人发 IM 消息），没有 `EnableRingInvitationView` 调用；
响铃是 TMSDK 的独立通道（腾讯会议账号之间），YX 的邀请统一走 IM。因此这里
默认开启但按可选能力提供，不依赖它完成邀请。
