# 官方客户端网盘功能实现分析

> 目标：以 `/Users/tom/Downloads/qmt/云上越秀.app`（5.2.97，Electron 21.3.1）内的网盘实现为基准，说明其认证、请求头、接口契约、目录规则与主要业务流程，并列出复刻版 `YX/` 的差异与错误。
>
> 证据来源：应用包内 `Contents/Resources/app/web/disk/**` 原始前端源码与 `web/html/static/js/home.*.js` 主程序包；线上接口探测使用当前账号 token（只读接口 + 不存在的 id 探测写接口）。REA fuse 证据 `ev_9f885b8c9c8fa170ce78efac39a86d05cbeee86ee103d3b781cd91a6f7b74b6e`（arm64，远程调试 fuse 开启）确认该包未被 ASAR 收拢，可直接读取上述源码。

## 1. 架构

```
云上越秀 Electron 主程序（web/html/static/js/home.*.js）
        │  pclinkStartIndex.html?accessToken=…&pc_port=…
        ▼
内置网盘前端（web/disk/html/app，AngularJS + seajs，版本 3.6.0）
        │  普通请求直连 openapi
        ├──────────────► https://{pan|yxgrouppan}.bingolink.biz/openapi
        │  上传/打开/同步
        ▼
本地云盘服务 CloudDiskServiceYXCloud（Go，127.0.0.1:<pc_port>）
```

- 主程序通过 `getV3AccessTokenByV2(localStorage.AccessToken)` 取得 v3 token，拼进 `pclinkStartIndex.html` 的 URL 参数（`accessToken`、`refreshToken`、`userId`、`pc_port` 等）。
- `pclinkStartIndex.html` 把参数写入 localStorage（`auth_accessToken`、`isPClinkHack=1`、`diskWebDir` 等），请求本地服务 `/config` 与 `/v1/settings/init`，再跳转 `…/app/disk/index/index.html`。
- `/config` 返回 `DiskConfigResult`（`api_url`、`app_id`、`version`、`device_id`、`os_name`、`ip` 等），是请求头取值的唯一来源。
- 上传、下载到本地、WPS 打开等走本地 Go 服务或 `wpsUri`；列表、删除、移动等直接调远程 openapi。
- 本地服务调用链：`bingodrive/pc_service/utils.GetDeviceID` 等；`web/disk/service/CloudDiskServiceYXCloud` 为 arm64 原生二进制。

## 2. 认证与请求头

`web/disk/html/app/ajaxSetting.js` 与 `main.js` 的 `$.ajaxPrefilter` 为每个请求注入：

| Header | 值 | 说明 |
|---|---|---|
| `Authorization` | `Bearer <auth_accessToken>` | 先 `decodeURIComponent` |
| `X-Requested-With` | `XMLHttpRequest` | |
| `Accept-Language` | `localStorage.langForApi` | |
| `appId` | `CONFIG.APP_ID` | `DiskConfigResult.app_id`，即 `BingoCloudDisk` |
| `appVersion` | `CONFIG.VERSION` | 本地服务 `/config` 的 `version`（包内 `web/disk/config.json` 为 `3.6.0`） |
| `Pan-Version` | `CONFIG.panVersion` | `GET /system/information` 返回的 `version`（当前生产为 `3.6.1`） |
| `deviceId` | `CONFIG.DEVICE_ID` | 本地服务设备号 |
| `os` | `encodeURIComponent(CONFIG.OS_NAME)` | |
| `x-forwarded-for` / `x-real-ip` | `CONFIG.IP` | 本地服务判定的客户端 IP |

其它要点：

- `$.ajaxSetup` 打开 `traditional: true`，数组参数以**重复键**发送（`files=Fx&files=Dy`），不是逗号拼接。
- 401：`ssoService.refreshAccessToken()` 刷新后重放；`app.ex.161` 视为登录失效并登出。
- 独立打开网盘（非 pclink 嵌入）时登录走 `{sso}/v2`（`credential_type=password`）+ `PCPAN` 客户端；嵌入模式直接用主程序传入的 v3 token。
- 下载地址带 `access_token`（query），不走 `Authorization`；详见第 5 节。

关键点：

- **删除载荷是 `类型+id`**：`hasPemissionArray.push(file.type + file.id)`，例如 `Fa25a3dc7-…`、`D9f0b2…`；复刻版只传 id。
- 重命名不是独立接口，而是 `move(from, "../新名")`。
- 列表默认排序 `[{by:'type',ascending:true},{by:'name'|'modifiedTime'|'size', ascending:…}]`；每页 100 条，`offset` 翻页。

### 3.3 团队 / 部门 / 公开文档

目录 path 规则：

| 用途 | URL |

### 3.6 文档接口（panServerUri，`/pan/v1`）

「群聊 → 任务与文档 → 团队文档」与云盘共用这套接口（`A = endWithSlash(localStorage.panServerUri)`，生产为 `https://pan.bingolink.biz/pan`）。目录 `dirId` 规则：个人文档 = `CurrentUserId`，团队文档 = teamId，部门文档 = orgId，公开文档 = classId，群文档 = 会话 id。

| 方法 | 路径 | 参数 |
|---|---|---|
| GET | `/v1/directories/{dirId}/items` | `access_token`（query） |
| GET | `/v1/directories/{dirId}/info` | `access_token` |
| POST | `/v1/directories/create` | `access_token`（query）+ JSON `{name, parentId}` |
| POST | `/v1/directories/delete` | `access_token` + `dirId`（query） |
| POST | `/v1/files/delete` | `access_token` + JSON `{ids: [fileId]}` |
| POST | `/v1/directories/rename` | `access_token` + JSON `{dirId, name}` |
| POST | `/v1/files/rename` | `access_token` + JSON `{id, name}` |
| POST | `/v1/directories/move` | `access_token` + JSON `{dirId, targetParentId}` |
| POST | `/v1/files/move` | `access_token` + JSON `{ids: [fileId], targetParentId}` |
| GET | `/v1/sign/download` | `fileId` |
| GET | `/v1/files/{fileId}/preview` | `access_token` |
| POST | `/v1/sign/upload`、`/v1/sign/upload/commit`、`/v1/sign/multipart/upload/*` | 上传签名与提交 |
| POST | `/v1/share/create` 等 | 分享 |

响应统一为 `{code, message, data, date}`；目录项为 `{id, name, type: "D"|"F", size, updatedAt, permissions}`。

**实测（当前账号）**：

- `GET /v1/directories/<CurrentUserId>/items` 返回个人文档 4 个文件；teamId、orgId、classId 同样可列。
- `POST /v1/directories/create` 创建临时目录成功，`POST /v1/directories/delete?dirId=` 删除成功（HTTP 200），无 `app.ex.666`。
- `POST /v1/directories/rename` 改名成功。
- 文件侧：`POST /v1/files/delete` 需 JSON `{ids:[id]}`（实测删除复制的临时文件成功）；`/v1/files/rename` 用 `{id,name}`；`/v1/files/move` 用 `{ids:[id],targetParentId}`；`/v1/files/copy` 用 `{ids:[id],targetParentId}`。
- `GET /v1/sign/download?fileId=` 返回签名下载地址；`GET /v1/files/{fileId}/preview` 返回预览地址。

这证明**网盘的写操作应走 panServerUri，而不是旧 `/openapi/file/*`**。

## 4. 旧接口与新接口的分工

| 能力 | 建议接口 |
|---|---|
| 各盘启用状态、团队/部门/公开文档列表 | `/openapi/system/info`、`/team/list`、`/org/list`、`/public/list_class` |
| 目录浏览、新建、删除、重命名、移动、下载、预览 | `/pan/v1/*` |
| 上传（复刻版） | 对象存储 `store/putFile` + `v2/{id}/share/document` |
| 搜索 | `/openapi/file/search`（只读，带 `keyword` + `bounds`） |
| 分享、关注、配额、版本、回收站 | 仍为 `/openapi/*`（读接口可用；写接口受 666 影响） |

### 4.1 上传（官方与复刻版）

官方磁盘上传走本地 Go 服务的 WebSocket（`/v2/pan/upload`）或 pan 的 `/v1/sign/upload`，两者最终都写 S3；`zs3.yuexiu.com` 在当前网络不可解析，复刻版无法直传。

复刻版改用已验证的「对象存储 → 文档服务」链路（与聊天附件保存到云盘相同）：

1. `POST {storeUri}/store/putFile?module=message&security=0`，multipart 字段 `file` / `fileName` / `size`，返回 `r.fileId`。
2. `POST {storeUri}/v2/{fileId}/share/document`，**表单**参数 `id=<fileId>&dirId=<目标目录 id>`，返回 `{"code":200}`。

个人盘、团队盘、部门盘、公开文档和团队文档均可用同一流程；`dirId` 规则同 3.6 节。

> 注意：`share/document` 写入的是文档服务（pan）的目录，`/openapi/file/list` 不会立即看到；复刻版的盘根会把 `pan` 列表与 `/openapi/file/list` 合并展示，避免历史文件消失。旧版官方客户端的盘列表是否能看到新上传文件，取决于服务端的同步策略。



## 5. 文件列表字段

`/file/list`、`/file/info` 的典型字段：

```json
{
  "id": "…", "principalId": "U…", "name": "…",
  "fullPath": "/Private/<principalId>/", "friendlyFullPath": "/个人文档/",
  "extension": "zip", "size": 107529073, "parentId": "…",
  "modifiedTime": "2023-01-18 16:48", "type": "F",
  "version": 1,
  "preview": { "available": false, "support": false, "needConvert": true, "status": "…" },
  "permissions": { "uploadable": true, "deleteable": true, "downloadable": true, "previewable": true, "shareable": true, "editable": true }
}
```

- **目录 path 必须由 `fullPath + name` 拼出**（`fullPath` 以 `/` 结尾），复刻版直接读 `path` 字段会得到空串。
- `type`：`F` 文件 / `D` 目录（不是 `isDirectory`）。
- 列表带 `options=withPermissions` 时才有 `permissions`。

## 6. 主要业务流程

1. **列表**：`file/list` 每页 100，`bounds.offset` 翻页，`orders` 排序，`options.dataLimitMode='hasMore'`；返回 `{rows, hasMore}`。子目录用 `fullPath + name`；搜索结果进入目录用结果里的 `fullPath` 反推。
2. **删除**：应用内确认 → `file/delete`（`files` 为 `类型+id` 数组）。`trashKeepDay=0` 时提示“永久删除”；否则进入回收站，可 `file/trash/list`、`restore`、`delete`。
3. **重命名**：`file/move`，`from=类型+id`，`to="../新名"`。
4. **移动/复制**：剪贴板记录 `{op, from:[类型+id…]}`，粘贴时 `file/move|copy(from, 目标目录 path)`。
5. **新建文件夹**：`file/check_dir_name` 校验重名 → `file/mkdirs`（path 为父目录 + 名称）。
6. **上传**：本地服务分片/队列，完成后刷新列表；远程不提供 `/file/upload`。
7. **下载**：浏览器/Electron 打开 `/stream/download?...&access_token=…`，由服务端 302 到 S3 签名地址。
8. **预览**：`/stream/preview`（WPS/WOPI），按扩展名与 `preview.available/support` 决定入口。
9. **回收站/分享/关注/版本/标签/属性**：见第 3 节接口。

## 7. 线上写接口返回 `app.ex.666`

对当前账号实测（token 为新登录取得的 link_desktop v3 令牌）：

- 读接口全部正常：`/file/list`、`/file/info`、`/file/chain`、`/system/info|information`、`/public/list_class`、`/perm/func/get_user_permissions`。
- 写接口全部返回 `400 {"code":"app.ex.666","message":"您当前使用的客户端版本需要升级，否则无法使用云盘功能！"}`：`/file/delete`、`/file/mkdirs`、`/file/move`、`/file/copy`、`/file/lock`。
- 已排除的因素：`appId`（BingoCloudDisk/BingoDrive/PCPAN 等）、`appVersion`（1.0.0–131.0.0、230、版本号组合）、`Pan-Version`（2.0.0–99.0.0、3.6.1）、`os`、`version`/`displayVersion`、`ClientType`、`deviceId`（有/无/改格式）、`x-forwarded-for`/`x-real-ip`（有/无/公网/内网）、`X-Client-IP`/`X-Client-MAC`、User-Agent（Electron/Chrome/Safari）、域名（`pan.`、`yxgrouppan.`、`streamapi.`）、请求体（裸 id、`F/D`+id、多值）、重新登录（含客户端 IP/MAC 头）。
- 结论：666 是旧 `/openapi/file/*` 写接口的退役策略，与请求头/参数形状无关；读接口仍放行。
- **解决方式**：改用 `panServerUri` 的 `/pan/v1/*`（同「任务与文档 → 团队文档」）。实测个人/团队/部门/公开目录均可列，新建、重命名、删除目录均成功，不再出现 666。复刻版已按此切换（见第 8 节）。
