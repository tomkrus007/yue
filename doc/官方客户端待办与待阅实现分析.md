# 官方客户端「待办 / 待阅」实现分析

> 分析对象：macOS 客户端 `云上越秀 5.2.97-arm64`（DMG）、Android 客户端 `BingoLink 5.2.96`（APK）
> 分析目的：解释复刻客户端（`YX/`）为什么只显示「您有一条新的待办」，并给出展示标题、打开详情的落地方案。
> 标记约定：**【观测】**= 代码/资源里直接读到；**【推断】**= 由代码逻辑推得；**【待确认】**= 缺少原始报文，需实测。

---

## 一、结论摘要

1. 待办通知是一条 `msg_type = 99`（COMPLEX）的复合消息，`content.brief` 固定为「您有一条新的待办」，真正的待办标题在 `content.contents[]` 里。官方会话列表、托盘气泡、搜索摘要**只取 `brief`**，所以列表里看到这句话是正常设计；但**气泡按 `content.type` 分支渲染**，标题、摘要、`更多`、图标都在气泡里显示。
2. `YX` 的 `complexToPlain()` 把 COMPLEX 一律拍平成「brief + contents[].content 字符串」，对 `type=5`（卡片）无效——卡片的 `contents[0].content` 是对象 `{title, brief, more}`，被 `typeof === 'string'` 过滤掉，于是只剩 brief。**这就是「只有您有一条新的待办」的直接原因。**
3. 消息本身**不带待办详情 URL**。`contents[0].action_param` 是 `[UnityTodo]` 标记 + `key=value` 参数（含 `defaultIndex`、`source`）。点击后的官方行为是：**切到消息面板里的「待办中心」tab，按来源过滤列表**，而不是直接打开某条待办。
4. 待办详情 URL 来自待办列表项的 `action` 字段（JSON 字符串，含 `{pc:"[OpenUrl]\nurl=..."}`），打开前必须兑换 CAS 票据：
   `GET {sso}/oauth2/authorize?response_type=create_session&…` 取 CAS TGT → `POST {casTicketUrl}{TGT}`（`service=待办URL`）取 ST → 打开 `{casUrl}login?token={ST}&service={待办URL}`。
5. 待办中心是**消息面板下的一个子 tab**（配置中心 `imlayout.ShowTodoTabInMsgView=true`），三个页签：待办 / 待阅 / 已办，角标 = `待办数 + 待阅数`。
6. `YX` 目前既没有 COMPLEX 分类渲染，也没有待办中心、`toDoUri`、CAS 兑换能力。最小修复是「消息侧按 type 渲染 + 卡片可点」；要真正打开详情，还需要补待办列表接口与 CAS。

## 三、消息侧：一条待办通知长什么样

### 3.1 消息结构【观测】

```jsonc
{
  "msg_type": 99,                 // COMPLEX
  "content": {
    "brief": "您有一条新的待办",
    "type": 5,                    // 渲染分支
    "contents": [
      {
        "content": { "title": "××审批单", "brief": "请于…前处理", "more": "…" },
        "img": "…",
        "action_type": 1,
        "action_param": "[UnityTodo]\ndefaultIndex=0\nsource=K2"
      }
    ]
  }
}
```

- 会话摘要：`getMsgBrief()` 的 `case 99` 直接 `return content.brief`，所以列表、托盘、通知、搜索摘要都是「您有一条新的待办」。【观测】
- 待办标题、摘要只在 `contents[]` 内，不进 `brief`。【观测+推断】

### 3.2 气泡渲染分支【观测】

`home.js` 的 `case 99:` 分支（`parseInt(content.type)`）：

| `type` | 渲染 | 数据位 |
| --- | --- | --- |
| `0` | 富文本 HTML | `ct = parse(contents[0].content)`，`action = contents[0]` |
| `1` | 可信富文本 | `contents[0].content`，`<style>` 加 `.third-party` 作用域、去 `<script>`、`<a>` 改走内置浏览器 |
| `2` | 图文列表 | 每项 `{title: item.content, img, action}` —— 即 `content` 是**字符串标题** |
| `3` | 线性表格 / 按钮 | `display_type` 1=表格（`content.column`）、4=按钮组、99=补充文案 |
| `5` | 卡片 | `{title: content.title, brief: parse(content.brief), img, more}` |
| 其它 | 兜底 | `content.brief` 当纯文本；没有 brief 才显示「不支持的消息类型」 |

另有 `isDirectReadedMsg`：`COMPLEX && type == 0` 视为无需回执的直接已读消息。

> **关键推断**：`YX` 只显示 brief，说明 `contents[].content` **不是字符串**（否则 `complexToPlain` 会把标题拼进去）。结合「type=5 卡片」的语义（标题 + 摘要 + 更多）与新待办通知完全吻合，可判定这条消息 **`content.type == 5`**，置信度高。【推断】

### 3.3 点击行为【观测】

`home.js` 处理消息内动作：

```js

```

`TodoViewSearch` 的消费方：

```js

  if (1 == e.defaultIndex) t = "read";      // 待阅
  else if (2 == e.defaultIndex) t = "done"; // 已办
```

要点：
- **不按 id 定位单条待办**，只切页签 + 按 `source` 过滤列表；`contents[0].action_param` 里没有待办 id。
- `splitActionParams` 用 `\n`（或字面量 `\n`）切分，再按第一个 `=` 拆 key/value。
- 若客户端没有待办 tab（旧版或被配置关闭），退化为用 `localStorage.toDoWebUri` 开独立窗口。

### 5.4 ST 是怎么换来的【观测 + 推断】

`linkplugin.getCasSTTicket` 只是 `appCallback('WidgetEventGetCasSTTicket', cb, [casUrl, casTicketUrl, serviceUrl])`，壳里的 JS 实现（`home.js` 内可见同构版本）为：

```js
getCasSTTicket: function (trigger, hostUrl, ticketBase, service, cb) {
  var host = hostUrl.match(/https?:\/\/([^\/]*)/)[1];
  setCookieLocal(null, true, function () {
    var tgt = getAppCookies(host);          // 上一步 create_session 拿到的 CAS TGT，按 domain 缓存
    if (!tgt) return cb("");
    ajax.post(ticketBase + tgt, { service: service }, function (st) { cb(st) }, function () { cb("") });
  });
}
```

`setCookieLocal(url, needTicket, cb)` → `needTicket` 时若 `AppCookieInvalidTime` 未过期直接回调，否则走：

```js
GET {ssoEndpoint}/oauth2/authorize
    ?client_id={clientId}
    &response_type=create_session
    &redirect_uri={ssoEndpoint}
    &logout_uri=
    &responseJson=true
    &access_token={AccessToken}
    [&cipher_token={CipherToken}]
```

响应 `{ tokens: [{ name, value, domain, path, expiresIn }] }`：把每个 token 同时种到 `http://{domain}` 与 `https://{domain}`，并在内存里按 `domain → value` 缓存（这就是 CAS TGT），另种一个 `redirect_to_on_authorize_fail`。`expiresIn` 用来刷新失效时间（默认 1800s）。

> 若 `oauth2/authorize` 返回 401，会按 `error_description.referral` 分流：`password_grant` / `refresh_token` / `retry` 自动重试，`relogin` 直接弹身份失效。

**归纳成可实现的四步（【推断】，需实测校验）**：

1. `GET {sso}/oauth2/authorize?response_type=create_session&responseJson=true&access_token=…&client_id=link_desktop` → 响应中的 `tokens` 即为 CAS TGT；
2. 按 `casUrl` 的主机名挑对应 token 的 `value`（TGT）；
3. `POST {casTicketUrl}{TGT}`，`application/x-www-form-urlencoded`，body `service={待办URL}` → 纯文本 ST；
4. 打开 `{casUrl}login?token={ST}&service={待办URL}[&token2=…&service2=https://sign.ysyx.com/]`。

## 七、Android 侧差异

APK 是 Flutter，业务在 `lib/arm64-v8a/libapp.so`：

- 独立模块 `package:unity_todo/…`：`UnityTodoEntity`、`UnityTodoHttpApi`、`UnityTodoRestClient`、`UnityTodoHomePage`、`UnityTodoFilterPage`、`UnityTodoInvoker`、`UnityTodoInvokerSwitchTabEvent`、`UnityTodoType`。
- 同样的接口：`/v1/api/todos`、`/v1/api/todos/count`、`/v1/api/toreads`、`toDoUri`、`defaultIndex`、`todoTaskIds`、`quickDeal`。
- 额外的原生待办入口：`/unity_todo/home`、`/unity_todo/filter`、`/unity_todo/filter_new`、`/unity_todo/select_type`、`/unity_todo/source_system`，以及统一搜索 `/unity/search`。
- 会话内切换待办 tab 用事件 `UnityTodoInvokerSwitchTabEvent`，与桌面端 `TodoViewSearch` 等价。
- **未在 `libapp.so` 中找到 `[UnityTodo]` 字面量**（桌面端有）。Android 大概率用 `action_param` 里的 `appCode`/`action_type` 走统一分发，或用 `defaultIndex` 直接解析。【待确认】

结论：两端功能同源，**桌面端代码更适合作为移植参考**（JS 可读、链路完整）。

| `YX/src/services/im/content.ts:180` `segmentsOf` | 只有 text/image/file 三类片段 | 无卡片、无图文列表、无按钮/表格、无动作 |

## 九、落地方案

### P0：消息侧正确渲染（解决「只显示一句话」）

目标：待办通知卡片显示 **标题 + 摘要 + 更多 + 图标**，与官方观感一致。

1. `content.ts` 新增 `complexToSegments(content)`，按 `parseInt(content.type)` 分支：
   - `0`：`contents[0].content` 作为 HTML 文本片段（现有 `looksLikeHtml` + `sanitizeHtml` 可直接复用）；
   - `1`：同 0，但标记为「可信富文本」（可复用同一渲染，仅样式作用域不同）；
   - `2`：`contents[].content` 作为条目标题，`img` 作为缩略图；
   - `3`：按 `display_type` 渲染表格 / 按钮（可先降级为文本）；
   - `5`：新增 `{ type: 'card', title, brief, img, more, action }` 片段；
   - 兜底：`content.brief` 纯文本（保持现状）。
2. `complexToPlain` 改为「按 type 取可读文本」，供摘要/转发/搜索使用；`type=5` 取 `title`（而不是 brief），`type=0/1` 取正文，`type=2` 用 `\n` 连接条目。
3. `MessageContent.vue` 增加 `card` 分支：标题（粗体）+ 摘要 + `更多` 折叠 + 图标；卡片可点。
4. 点击行为（P0 可先降级）：识别 `action_param` 中的 `[UnityTodo]`，弹出提示「请在待办中心查看」，P1 再接跳转。

> 验收：找到一条待办通知，气泡应显示待办标题；会话列表仍显示「您有一条新的待办」。

### P1：待办中心（只读列表 + 打开详情）

1. `config.ts` 补 `toDoUri?: string`；运行时 `getServerPaths().toDoUri`。
2. 新增 `src/services/im/todo.ts`：
   - `listTodos({page,limit,title,total,startTime,endTime,tags,source,dealTerminal,orderBy})` → `/v1/api/todos`
   - `counts()` → `/v1/api/todos/count` + `/v1/api/toreads/count`
   - `listToreads()` / `listDone()` / `sources()` / `dict()`
3. 新增 `views/TodoView.vue`：三个页签 + 角标 + 分页 + 搜索；卡片字段按 4.3。
4. 消息卡片点击 → 切到 `TodoView` 并按 `source` 过滤（对齐官方 `TodoViewSearch`）。
5. 详情 URL：`getTodoUrl(item.action)`（照抄 5.1 的解析），`dealTerminal == 3` 直接提示。

### P2：CAS 打开外链

1. 新增 `src/services/im/cas.ts`：
   - `getCasTokens()`：`GET {sso}/oauth2/authorize?response_type=create_session&responseJson=true&…`，从 `tokens` 里按 domain 取 TGT，缓存 `expiresIn`；
   - `getSt(casTicketUrl, tgt, serviceUrl)`：`POST {casTicketUrl}{tgt}`，表单 `service=…`，返回纯文本；
   - `buildCasUrl(todoUrl)`：集团/地产双 ST + 最终 `login?token=&service=&token2=&service2=`。
2. 用 `@tauri-apps/plugin-opener` 的 `openUrl` 在系统浏览器打开——**注意**：CAS 登录会在浏览器里种 cookie，因此只能走外部浏览器，不能在 Tauri webview 的 iframe 里复用（`plugin-http` 与 webview cookie 不互通）。
3. 若 `ToDoCasUrls.casExact` 命中，直接按表选租户，省掉 `jump/cache`。

### 风险与依赖

- **CAS 票据接口需实测**：`oauth2/authorize` 的 `tokens[].domain` 与 `casUrl` 主机是否一致决定 TGT 选取；若不一致（例如 token 域是 `.yuexiu.com`、CAS 域是 `sso1.yuexiu.com`），需要按后缀匹配。
- `toDoUri` 是否随配置中心下发需抓一次 `config/server/configs/yuexiu` 响应确认（参考库已给出 `https://gw.yuexiu.com/todosrvapi`）。
- 待办列表接口可能需要额外头（`ClientType`、`deviceId`、`version`），照官方 `ajax` 默认头补齐。
- CSP：P2 只打开外部浏览器，无需改 CSP；若做应用内 iframe，需要 `src-tauri/tauri.conf.json` 放行对应域名。
