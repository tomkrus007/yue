# 消息 P1–P3 实现与统一验收

更新日期：2026-11-13。本轮按用户要求先实现 P1–P3，只进行构建、离线模拟和本机测试；P0 生产跨端验证尚未执行。以下“已实现”表示代码链路和对应离线回归已完成，不表示生产环境已经验收。

## 实现依据与边界

- 官方 5.2.97 随包 `home.7717570b45127039f907.js` 提供了 CTRL `1000/1001` 回应、`reply_msg_id` 引用、95 阅读确认、13 发送回执及合并明细上传的静态依据。参考项目使用仓库内 `yx-cloud-kb`。
- 回复补全使用已有 `GET {embQueryUri}/get/history/date`，固定 `dateTime` 并递增 `skip`；没有伪造“按原消息 ID 查全部回复”的接口。完整扫描仅覆盖该查询上界前、当前账号有权取得的历史。大群扫描可以停止，当前请求可中止，之后继续保留游标。
- 未从官方源码确认独立的 `forwardMsgDetailId` 读取接口。只有 ID 而没有明细的记录，先找已取得的同 ID 明细，再从已核实的历史接口补载；服务端仍不下发时显示原因。该场景应在 P0 保存脱敏的真实响应后继续核对。
- 群回执名单来自发送时发起的成员查询，不冒充服务器保存的历史成员。分页去重数量必须与已核实总数一致才标完整；部门只处理已核实的本人部门查询范围，超过 800 人或总数未知时明确说明不完整。已收到确认与尚未收到确认是本机观察，不能把后者断言为未阅读。
- 目前未覆盖会议、动态、本机专有插件、缺少电脑地址的内置应用及全部自定义皮肤。卡片动作只在用户实际点击时执行，未知指令不猜 URL 或执行代码。
- 播放器只访问带不透明租约的本机地址；外部业务 HTTP 仍由 `@tauri-apps/plugin-http.fetch` 处理。响应分片最多 256KB，通过 `invoke(cmd, Uint8Array, { headers })` 写文件或媒体管道，Rust 不为下载／播放新增外部 HTTP 请求。文件及媒体访问按账号生命周期清理。
- ffmpeg 不是新增的捆绑依赖，不自动安装；本轮未验证真实编码转换。没有工具或仍不支持的编码，提供系统播放器降级。
- 提醒处理状态与待发送队列保存在本机，服务端没有已核实的同类工作流同步接口。异地设备的“打开会话”不会被假定成“已经处理提醒”。

## 已进行的验证

前端质量门禁：在 `YX/` 执行 `pnpm build`，包含严格类型检查及生产构建。

离线回归共 16 个脚本，均在 `YX/scripts/`：

- `check-message-center.cjs`、`check-message-store.cjs`、`check-message-interactions.cjs`：限次发送、断线／重启、乱序确认、提醒处理、95 队列、焚毁、跨端游标与真实 ChatView 初始化。
- `check-auth-lifecycle.cjs`：同账号刷新去重、失败后重试、换号／注销的迟到响应隔离；IM 回归另覆盖旧刷新定时器不干扰新会话及旧附件不在新账号发送。
- `check-history-pager.cjs`：同毫秒多页消息、固定上界、并发去重、重复／循环页、超时、中止及重试游标。
- `check-forwarding.cjs`：引用快照、嵌套字段清理、附件、分批顺序、单条超限、详情缓存及内层会话身份。
- `check-message-favorites.cjs`、`check-favorites-sync.cjs`：真实收藏协议、全量分页、同步竞态、账号切换、定位歧义及热查询索引。
- `check-card-actions.cjs`、`check-cards.cjs`、`check-preview-mapping.cjs`：指令、应用／名片、上下文、提交参数与预览地址映射。
- `check-transfers.cjs`：响应流背压、原始字节 IPC、进度、取消／写盘失败清理、401 刷新、Range 与租约关闭。
- `check-receipts.cjs`：名单快照、分页完整性、账号隔离、迟到响应及回执弹窗逻辑。
- `check-notifications.mjs`、`check-unread.mjs`、`check-todo.cjs`：保留原有通知、未读隔离和待办行为。

原生侧在 `YX/src-tauri/` 执行 `cargo test --lib`：9 项通过，4 项真实零信任测试保持忽略。下载和媒体使用本机假服务／socket，不访问生产服务。离线与服务端渲染冒烟不能代替桌面 DOM、实际播放器和生产互通。

## 统一 P0 验收顺序

验收前重启 `pnpm tauri dev` 或重新启动新构建，确保新增原生命令和媒体 CSP 生效。需要可用生产账号及可接收消息的原版客户端；以下尚未执行。

| 场景 | 操作 | 可观察的通过标准 |
| --- | --- | --- |
| @ 提醒 | 原版在两个群 @ 本账号；打开群、逐条回复／收到、重启客户端 | 会话未读与待处理分开；只在确认成功后完成对应提醒；前后切换、撤回和重启状态正确。 |
| 引用与回复 | 双向回复文字、图片、文件；打开较早讨论并暂停／继续补全 | 双端引用关联一致；原文和关联回复补齐；扫描范围、错误、取消均可见，无强制滚动或漏页。 |
| 断线发送 | 使用约定测试会话发送后短暂断网，再恢复；观察明确拒绝及确认超时 | 复用同一编号，无重复落库；状态可恢复，显式拒绝不循环重发，失败理由可见。 |
| 转发 | 混选附件、引用与嵌套记录，多接收人发送；总量超过单条合并上限 | 分批顺序完整、无漏重；原版可打开明细；文件权限失效仍清楚提示，ID-only 场景可脱敏留证。 |
| 收藏 | 两端分别收藏／取消，然后切回本客户端；定位重复内容 | 完整同步后星标一致，分页失败不清空状态；多条同内容记录由用户选择来源。 |
| 卡片 | 测授权应用、服务号、待办链接及带输入的提交卡片 | 对应目标正确打开，服务号不会变个人会话；只有点击才发提交，错误有具体说明。 |
| 下载与播放 | 大附件下载后取消／重试；音视频边播边拖动、关闭播放器、切换账号 | 内存不随文件总大小增长；取消无残留、重名不覆盖；Range 播放正常，旧账号不继续取新内容。 |
| 回执与焚毁 | 单聊与群发送回执消息，跨端查看；焚毁打开后关闭或重启 | 95 确认状态准确，人员／时间及名单范围清楚；本机正文不复活，原版一侧状态一致。 |

生产异常只需记录脱敏的消息类型、回执结构、分页参数及错误阶段，不把 token、密码、完整请求地址或业务正文写入文档。
