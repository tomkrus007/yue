# 官方客户端组群功能实现分析

> 目标：以官方 macOS 客户端（仓库 `yx-packages/yuexiu_1786088172677.dmg`，云上越秀.app，Electron；主程序包 `web/html/static/js/home.*.js`，压缩未混淆）内的「组群」（创建群聊）实现为基准，说明入口、接口契约、建群后的会话行为与本地数据模型，并列出复刻版 `YX/` 的缺失项与落地方案。
>
> 证据来源：应用包内未混淆 web 源码（`home.*.js`）、`web/init.sql`（本地库 schema）、`web/i18n/zh-CN.json`（UI 文案）；Android 官方客户端 APK 的 `lib/arm64-v8a/libapp.so` 字符串池（`strings`）交叉验证；并与 `yx-cloud-kb/kb/` 既有结论（EMB 协议命令码表、`groups/joined`、`templateCode`）对照。
>
> 本文**未对生产环境做任何写操作**；`v2/groups/create` 的请求体是直接读官方源码得到的，其生产实测行为见第 8 节待验证项。

## 1. 总体架构：组群是 UAM 纯 REST 操作，IM 长连接不参与

- 群是用户中心（UAM）域实体：建群 = `POST {uamApiUri}/v2/groups/create`，请求头即标准 uamapi 头（`Authorization: Bearer` + `version` / `displayVersion` / `ClientType` / `deviceId`），**JSON body**（官方封装 `contentType:"application/json"`）。
- EMB 长连接协议**没有"建群"命令**。命令码全集（`uBeats 6 / uLogout 7 / uAuth 11 / uSendMsg 3 / uReadedSession 19 / uOnlineStatus 24 / uListenOnlineStatus 26 / uError 98 / uOfflineStart 102 / uSessionCursor 105`，见 `yx-cloud-kb/kb/proto-emb-websocket.md`）中无任何群创建语义。
- 群聊会话靠两条路径出现（均为客户端本地行为，见第 4 节）：
  1. 创建者：建群成功后本地 upsert 一条会话记录并直接打开，不依赖服务端推送；
  2. 其他设备：首条消息推送到达后按归属规则补会话（`to_type ∈ {2,4,8} → 会话归 to_*`，kb 已有结论）。
- 因此复刻组群只需要三件事：**1 个 REST 调用 + 本地会话 upsert + `to_type=2` 发消息**——后两者 `YX` 已具备，缺口只有 REST 与 UI。

## 2. 入口（三处，全部收敛到同一个选择窗）

| 入口 | 触发 | 行为 |
|---|---|---|
| 联系人选择窗 | 多选 ≥2 人点确定 | 自动转建群（回调 `k(e)`，不带标记） |
| 联系人选择窗 | 只选 1 人点确定 | 开单聊，不建群 |
| 用户卡片"组群"图标 | 点 `icon-chatcreategroup` | `openSelectUser {type:"GroupCreate", selectedUsers:[对方, 自己]}`，两人默认勾选、可取消 |
| 我的关注列表 | 点 `createGroup` | 打开 QuickStart 快捷窗（`u.a.open({code:"QuickStart_Chat"})`，即主窗"发起聊天"） |

细节：

- 选择窗按 `type` 渲染不同通讯录树；`GroupCreate` 类型 = 好友 + 组织（`needMyGroup:false, needMyFriend, needOrg:true`），**不含群**，即"在同事里挑人"。
- 回调分发 `dealWithSelectUser(e)`：`case "GroupCreate": k(e, true)`——第二个参数 `true` 表示**即使只剩预选的 1 个人也强制建群**（StartChat 的 `k(e)` 会在单人时退回单聊）。
- 窗口标题 i18n `Window_Title_CreateGroup` = "创建群组"。

## 3. 接口契约

### 3.1 建群 `POST {uamApiUri}/v2/groups/create`（观测）

官方建群回调 `k(e, t)` 的完整逻辑（`home.*.js` 中）：

```js
function k(e, t) {                                  // e = 选择窗结果, t = 是否强制建群
  if (!t && 1 == e.selectedUsers.length) { ...OpenChat(单聊); return }   // 单人 → 单聊
  var i = M()                                       // 自己：{id, name, type:1, isDefaultUser:true}
  var s = [i], users = [], name = i.name, l = 1
  e.selectedUsers.forEach(t => { if (t.id != i.id) s.push({id: t.id, name: t.name}) })
  s.forEach(t => {
    var role = (t.id == i.id) ? 2 : 0               // 2=群主(自己)  0=普通成员
    if (t.id != i.id && l < 3) name += "," + t.name, l++   // 群名 = 前 3 人姓名逗号拼接
    users.push({ memRole: role, id: t.id })
  })
  c.createGroup({ name, users }, ok, fail)          // POST v2/groups/create
  // ok: code==200 → OpenChat({id: data, type: 2, name})
  // fail: toast(message || i18n.Group_Tip_CreateFail)
}
```

请求体与字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 群名。**默认 = 前 3 位成员姓名逗号拼接**（含自己，数到 3 个为止）；官方流程没有独立的群名输入框（推断建群后只能走"更新群"改名） |
| `users` | array | 成员列表，**自己永远排第一** |
| `users[].memRole` | int | `2` = 群主（自己），`0` = 普通成员 |
| `users[].id` | string | userId |

- 请求头：标准 uamapi 头（Bearer token + `version` / `displayVersion` / `ClientType: pc` / `deviceId` / `X-Requested-With`），与 `YX` 现有 `contact-client.headers()` 一致。
- 响应：成功判定 `code === 200`，**`data` 直接就是新群 id**（字符串，官方直接拿它当会话 id 用）；失败取 `message` 弹 toast。
- **不传模板参数** → 建出来是普通群（详情 `templateId: "groupDefault"`）。`v3/groups/create`（团队空间用）在桌面端**定义了但 0 处调用**，是死端点，组群不涉及。

## 4. 建群之后的会话侧（观测）

`home.*.js` 中 `OpenChat` 事件的订阅端：

```js
u.a.subscribe("OpenChat", function (t) {
  if (!e.isInitedSessionList) { e.afterInitedSessionList = ...; return }
  t.onlyAddView || (切到消息 tab);
  t.isSubScription ? i() : e.addSession(t, i);   // 会话列表里没有就先补本地记录
  function i() { n.openChatView(t) }             // 再打开聊天页
})
```

`addSession` 的逻辑：本地 `message_session` 表已有该 `sessionId` → 只更新时间；没有 → `getMsBehavior` + 查本地库（没有则建记录）→ `pushSession` 进会话列表。

要点：

- **建群后不发任何 WS 帧、不调任何 IM REST**；会话是纯本地 upsert 出来的。
- 聊天页打开后按惯例拉历史（`get/history/date`），新群为空属正常。
- 首条消息按 `to_type: 2` 发出后，服务端会话才真正生效；其他设备靠消息推送补会话。
- 推断：空群（建了没人发消息）不会出现在 `emb/sessions/latest`（该接口按 `lastMessage` 聚合，kb 已确认），只影响其他设备/重连时的会话列表，不影响本端。

## 5. 本地数据模型与移动端交叉验证

**桌面端本地库（`web/init.sql`）关键表：**

```sql
create table if not exists groups(
  groupId TEXT PRIMARY KEY, name TEXT, ownerId TEXT, memberRole INTEGER,
  memberCount TEXT, joinMode INTEGER, isPublic INTEGER, maxMemberCount INTEGER,
  msgReceiveType INTEGER, silentStatus INTEGER, lastUpdatedDateOnServer INTEGER, ...);
create table if not exists group_members(
  groupId TEXT, userId TEXT, memberRole INTEGER DEFAULT 0, isDeleted TEXT,
  nickName TEXT, silentStatus INTEGER, status INTEGER, namePinYin TEXT,
  primary key(groupId, userId));
CREATE TABLE if not exists message_session(
  talkWithId TEXT PRIMARY KEY, topTime INTEGER, tag TEXT,
  isNoNotify INTEGER DEFAULT 0, unReadCount INTEGER DEFAULT 0, draft TEXT, msgId TEXT);
```

`memberRole`（群成员角色，群主=2）是本地缓存群成员的字段，与建群 body 的 `memRole` 同义。

**APK（`libapp.so` 字符串池）交叉验证：**

- `/v2/groups/create` 存在（移动端走同一 v2 接口）；`/v3/groups/create` 也存在（团队空间线，`/v3/groups/formal/page?scope=1&limit=`）。
- 本地库含 `GroupUser(groupId, userId, memberRole, ...)`、`GroupApply`（入群申请）、`GroupRobot` 表；`processGroupCreate` 为处理流程名。
- `memRole` / `memberRole` 语义两端一致。

## 6. `YX` 复刻现状与缺失

| 能力 | 状态 |
|---|---|
| 会话本地 upsert / 打开聊天（`im.openChat(id, name, 2)`） | ✅ 已有（`stores/im.ts`），建群后直接复用 |
| 群消息发送（`to_type=2`）、历史、未读、免打扰/折叠/置顶 | ✅ 已有 |
| 群选择器数据源（`searchEntries` 含群 + 全员搜索）、群成员（MentionPicker） | ✅ 已有 |
| `POST v2/groups/create` REST 封装 | ✅ 已实现（`contact-client.createGroup`） |
| 组群 UI（入口 + 弹窗） | ✅ 已实现（`ContactsView` 头部「创建群组」+ `components/CreateGroupModal.vue`） |

顺带发现的不一致：`contact-client.getGroupDetail` 原先用的是 `v1/groups/{id}/detail`，而官方与 kb 实测均为 `v2/groups/{id}/details`（`prefs.ts` 的 `isTeamGroup` 已经用 v2）；实现组群时已统一成 v2。

### 6.1 复刻实现差异（有意为之）

- 官方没有群名输入框，名字固定取前 3 人姓名；复刻版把默认值填进输入框且允许修改，避免建完再走改名接口。
- 成员列表只列同事（好友 + 全员搜索），不含群，对齐官方 `GroupCreate` 的 `needMyGroup:false`。
- 自己固定置顶、勾选且不可取消，`memRole` 恒为 2；至少选 1 位同事才能提交（官方在 `GroupCreate` 下即使只剩预选 1 人也强制建群，等价于「自己 + 1 人」）。

## 7. 落地方案（`YX`）

1. **REST**：`src/services/contact-client.ts` 增加

   ```ts
   /** 建群：POST {uamApiUri}/v2/groups/create，JSON；成功返回新群 id */
   async createGroup(name: string, users: { memRole: number; id: string }[]): Promise<string>
   ```

   请求头复用 `headers()`；`code !== 200` 抛 `message`；`data` 即群 id。
2. **UI**：`ContactsView.vue` 头部加"创建群组"按钮（官方文案），弹窗 = 群名输入（默认值 = 前 3 位所选姓名逗号拼接，**允许编辑**——比官方多一步，避免建完想改名）+ 成员多选（复用 `searchEntries` 的搜索/勾选交互；自己默认选中、置顶、不可取消，`memRole` 恒 2，其余 0）。
3. **收尾**：成功后 `im.openChat(群id, 群名, FromType.GROUP)` 跳聊天页（对齐官方 `OpenChat` 行为）；同时 `loadContacts()` 刷新通讯录群列表。
4. **边界**：群主转让 / 解散 / 入群审批 / 邀请码 / 公告 / 禁言属"群管理"，不在组群范围（接口与落地方案见 [官方客户端群管理实现分析](./官方客户端群管理实现分析.md)）；团队空间（v3 / formal / 升级工作空间）也不在组群范围。免打扰 / 折叠 / 置顶沿用现有会话卡片能力。

## 8. 待验证项（生产写操作，需用户明确要求后用真实账号执行）

1. `v2/groups/create` 的 `data` 返回形态（推断为群 id 字符串；官方代码直接当会话 id 用，未实测）。
2. 响应是否携带 `ownerId` / `templateId` 等字段（官方未读取，复刻可忽略）。
3. 新建空群是否会出现在 `emb/sessions/latest`（推断不会；首条消息后才聚合）。
4. 建群后服务端是否下发系统通知帧（官方无任何特殊处理，推断聊天窗为空）。
5. `ClientType` / `version` 请求头对该写接口的敏感度（同域读接口 `groups/joined` 已跑通，风险低）。
6. 验证姿势建议：用测试账号建一个含自己 + 1 位可联系同事的 2 人小群，发一条消息确认对端可见，再解散（`/v2/groups/{id}/dismiss`），避免留下垃圾群。
