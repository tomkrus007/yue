# 腾讯会议（Tencent Meeting SDK）移植到 YX 的可行性评估

> 结论先行：**可行，但代价高**。腾讯会议在官方客户端里是「一整个原生应用」以 framework 形式外挂（357 MB，arm64-only），
> 会前主页、入会、会中界面、投屏、历史、预约全部由腾讯 SDK 自绘。YX 要做的是**原生桥 + 打包 + 权限 + IM 联动**，
> 不需要重写会议 UI；但原生框架的集成、签名/公证、摄像头麦克风权限、无测试账号联调会把工作量推高。
>
> 观测基线：`yx-packages/yuexiu_1786088172677.dmg`（云上越秀 5.2.97-arm64，TMSDK 3.21.303，2024-05-21）。
> 本文把「观测」与「推断」分开标注；未实测的结论都按风险项列出。
>
> **P0 进展**：原生初始化/回调/退出已在最小 `.app` 壳里跑通（假 token 也能 `init success`），
> 详见 [`腾讯会议P0验证记录.md`](./腾讯会议P0验证记录.md)。仍需真实账号验证配置接口与会前窗口。

---

## 0. 一句话结论

| 维度 | 判断 |
|---|---|
| 技术可行性 | 可行（Tauri v2 支持 `bundle.macOS.frameworks` / `entitlements` / `infoPlist`） |
| 业务逻辑量 | 小：官方只用了 12 个原生函数 + 10 个回调事件 |
| 集成难度 | 高：357 MB 原生框架 + 独立 helper 进程 + 签名/公证 + TCC 权限 + 主线程 |
| 体积代价 | YX release 包当前约 14 MB，移植后约 **370 MB**（+26 倍） |
| 平台 | 只能 **arm64**（TMSDK 无 x86_64 slice），Intel Mac 不可用 |
| 预估工作量 | 最小可用 **10–15 人天**；完整（含邀请卡片/响铃/纪要）**17–30 人天**；单人约 3–6 周 |
| 最大不确定项 | 非官方客户端能否直接调 `/v1/tencent/meeting/config` 拿到 sdkToken；仓库无测试账号 |

## 1. 原版实现解剖（观测）

### 1.1 交付物形态

```
云上越秀.app/Contents/
├── Frameworks/
│   └── TMSDK.framework/                        357 MB（arm64-only）
│       └── Versions/A/
│           ├── TMSDK                            127 KB（ObjC 门面，ver 3.21.303）
│           ├── Headers/                         TMSDK*.h / wemeet_sdk*.h
│           └── Frameworks/tmsdk_wemeet_sdk.framework/     C++ 封装
│               └── .../Frameworks/TMSDKFramework.framework/  355 MB
│                   └── ...（Qt / skia / ffmpeg / WeMeet / xcast / 40+ 业务模块）
│               └── .../Resources/TMSDKHelper.app/          90 KB 启动器（独立进程）
└── Resources/app/src/plugins/wemeet/
    └── wemeet_electron_sdk.node                550 KB，N-API 插件
```

关键观测：

- `TMSDK.framework` **arm64 单架构**，`LSMinimumSystemVersion 10.11`。
- 内嵌 `TMSDKHelper.app`（`com.tencent.TMSDKHelper`，`LSUIElement=true`，自带相机/麦克风用途说明），
  对应 SDK 的 `CreateIndependentProcess` / `CreateFakeProcess`，**推断会议 UI 实际跑在独立进程里**（需 spike 确认）。
- `wemeet_electron_sdk.node` 是**纯 N-API 插件**，只依赖 `@rpath/TMSDK.framework/...` 和 `libc++`，
  不依赖 Electron；导出 `GetWemeetSDKInstance` 等 C++ 符号（底层走 `tmsdk_wemeet_sdk` 的 C++ 接口，不是 ObjC 门面）。
- 整包安装后 1.0 GB，其中 `Resources/app` 410 MB、`Frameworks` 614 MB，TMSDK 占 357 MB。

### 1.2 调用链（前端 → 主进程 → 原生）

```
渲染进程 web/html/*.js
  app.wemeet.init/join/quickMeetingByJson/toHomeView/bringViewTop/logout/releaseSDK
        │ ipcRenderer.send('NativeApiOnMain', { method: 'wemeetXxx', params })
        ▼
主进程 src/MainProcess.js  wemeetInit/wemeetJoin/...
        │ require('./plugins/wemeet/wemeet_electron_sdk.node')
        ▼
wemeet_electron_sdk.node  →  GetWemeetSDKInstance()  (C++)
        │ ISDKCallback / IAuthenticationCallback / IPreMeetingCallback / IInMeetingCallback
        ▼
AddJsCallback(cb) → this.trigger('WemeetEvent', [cbMsg])  → 渲染进程 app.listen('WemeetEvent')
```

### 1.3 官方实际用到的原生面（12 个函数）

`InitWemeetSDK`、`AddJsCallback`、`SetNeedShareCallback`、`Login`、`RefreshSDKToken`、`IsAuthorized`、
`JoinMeeting`、`QuickMeetingByJSON`、`BringInMeetingViewTop`、`ShowPreMeetingView`、`Logout`、`ReleaseWemeetSDK`。

对应回调事件：`OnSDKInitializeResult`、`OnLogin`、`OnLogout`、`OnJoinMeeting`、`OnLeaveMeeting`、
`OnInviteMeeting`、`OnDissolveMeeting`、`OnForcedLogout`、`OnShowAddressBook`、`OnRingInvitationEvent`、`OnSDKError`。

> 这说明「会议业务」几乎全在 SDK 内部；YX 侧只是薄桥。

### 1.4 账号与登录

```text
GET  {rtcUri}v1/tencent/meeting/config
  → { sdkKey, sdkToken, ssoUrlPrefix, idToken }
InitWemeetSDK(sdkId, sdkToken, data_path, '网络会议', '')
Login(ssoUrlPrefix + idToken)        // 带登录态拉起腾讯侧账号
data_path = cacheDataPath + CurrentUserId + '/wemeet_cache'
```

- `rtcUri` 来自配置中心下发的 `serverPaths.rtcUri`（**YX 当前没有这个字段**）。
- 初始化后若 `IsAuthorized()==1` 视为已登录；`RefreshSDKToken` 返回 0 表示成功。
- 错误码约定：`OnLogin` 的 `0` / `-1012` 视为成功。

### 1.5 与 IM 的联动

- **邀请卡片**：`msgType = 99`（COMPLEX）+ `type = 5`，`action_param` 里带
  `[JoinWeMeet]meetingCode=...` 或 `[OpenApp]appCode=linkMeeting&supplier=tencent&meetingCode=...`。
- **视频通话消息**：`msgType = 15`（`VIDEOCHAT`），`[StartWeMeet]` / `[JoinWeMeet]` 动作。
- **发邀请**：`app.linkplugin.sendMsg({msgType: 99, content: <富文本>})`。
- **入会入口**：`doBehavior` 解析命令行 `wemeetjoin`；`YXCloud://` URL scheme 走 `open-url`。
- **响铃邀请**：`OnRingInvitationEvent` 弹窗，32 秒超时。

### 1.6 配置开关（观测）

```json
"useWeMeet": 1,        // 腾讯会议（主用）
"useXYMeet": 0,        // 小鱼易连（mac Apple Silicon 明确不支持）
"useVideoChat": 0,     // AGORA 视频通话（另一套，未启用）
"videoChatType": "AGORA"
```

> 注意：`startMeeting.html` / `xyMeeting.html` 那套是**小鱼易连**的 HTML 界面，与腾讯会议无关；
> 腾讯会议只有原生 UI，没有网页版会议界面。

## 3. 四种方案对比

### 方案 A：Tauri 内嵌 C++ 桥（推荐）

在 `src-tauri` 里写一个 C++ shim（`wemeet_shim.cc` + `wemeet_shim.h`），用 `cc` crate 编译并链接
`tmsdk_wemeet_sdk.framework`，实现 `ISDKCallback` / `IAuthenticationCallback` / `IPreMeetingCallback` /
`IInMeetingCallback`，把回调序列化成 JSON 字符串，通过 `extern "C"` 函数指针交回 Rust，再 `emit` 成 Tauri 事件。

- 优点：不引入 Node 运行时；进程模型简单；与 YX 现有 `zt_sdk` 的「Rust 驱动原生」风格一致。
- 缺点：要处理 `@rpath`、主线程、TCC、签名公证；357 MB 框架必须随包分发。
- 关键实现点：
  - `bundle.macOS.frameworks: ["TMSDK.framework"]`，整目录原样拷进 `Contents/Frameworks`（rpath 是相对 `@executable_path` 的，必须保留嵌套层级）。
  - `bundle.macOS.hardenedRuntime: false`，或 entitlements 加 `com.apple.security.cs.disable-library-validation`（腾讯框架含 helper，验证会拦）。
  - `bundle.macOS.infoPlist` 增加 `NSCameraUsageDescription` / `NSMicrophoneUsageDescription`。
  - 初始化必须 `app_handle.run_on_main_thread(...)`；回调线程与 UI 线程分离。
  - `TMSDKHelper.app` 是嵌套 `.app`，公证时要一并签。

**预估：最小闭环 10–15 人天，含邀请/响铃 17–24 人天。**

### 方案 B：独立 helper 进程复用官方 `.node`

官方插件是纯 N-API，可原样在独立 Node 进程里 `require`，暴露 localhost JSON-RPC（仿 `zt_sdk` 的 35440–35443 模式），
Tauri 只做 HTTP 客户端。

- 优点：**不写任何 C++/ObjC 桥**，直接复用腾讯官方封装；崩溃隔离。
- 缺点：要随包分发 Node 运行时（+80–100 MB）；helper 需要是独立 `.app`（TCC/激活策略）；进程生命周期、端口、日志都要自己管；
  与 YX 现有 Rust 侧风格不一致。
- **预估：8–12 人天**（比 A 少写桥，但多进程运维）。

### 方案 C：委托官方客户端（最省）

官方客户端注册 `YXCloud://` 并支持 `wemeetjoin` 命令行行为，理论上 YX 可以 `open -a 云上越秀 --args ...` 或 URL 唤起入会。

- 优点：几乎零集成。
- 缺点：**依赖官方客户端已安装并常驻**（AGENTS.md 只保证装了零信任客户端，不保证装云上越秀本体）；UX 割裂；
  URL 参数格式需逆向确认；无法做「YX 内开会」。
- **预估：2–4 人天**，只适合做兜底/降级。

### 方案 D：自绘 Web RTC

用腾讯 TRTC / Agora 自己做会议 UI。

- 缺点：等于从零实现会前、会中、投屏、录制、美颜、降噪、弱网，**成本高一个数量级**，且不是「腾讯会议」。
- 不推荐。

### 对比表

| 方案 | 工作量 | 体积 | 体验 | 风险 |
|---|---|---|---|---|
| A 内嵌 C++ 桥 | 10–24 人天 | +357 MB | 原生腾讯 UI，完整 | 签名/公证/线程 |
| B helper 复用 .node | 8–12 人天 | +450 MB | 原生腾讯 UI，完整 | 多进程运维 |
| C 委托官方客户端 | 2–4 人天 | 0 | 割裂，需已安装 | 依赖外部 |
| D 自绘 RTC | 60+ 人天 | 视 SDK | 自研 | 不推荐 |

> **推荐 A**；若只想快速验证价值，先做 C 或 B 的 spike。

## 5. 风险与未知项（按影响排序）

1. **授权/合规**：`sdkKey/sdkToken` 由越秀服务端下发，腾讯会议 SDK 是商业授权产物；二次分发 357 MB 专有框架需确认企业许可，
   SDK 许可协议也可能限制逆向/再封装。**需法务/平台侧确认。**
2. **非官方客户端能否直接调接口**：`/v1/tencent/meeting/config` 是否校验 User-Agent/客户端签名/版本，未实测；
   若被网关拦截，方案 A/B 直接失效。**这是 P0 必须验证的第一件事。**
3. **测试账号**：仓库无可用账号，端到端只能靠真实越秀生产账号 + 腾讯会议企业授权，联调排期不可控。
4. **签名/公证**：`TMSDK.framework` 内含 `TMSDKHelper.app`、40+ 嵌套框架，公证需全部签名；hardened runtime 下 library validation 会拦，
   需 entitlements 放行（与官方 Electron 的做法一致）。
5. **体积**：+357 MB，安装包从 14 MB 涨到 ~370 MB；升级/分发成本上升。
6. **架构**：TMSDK 无 x86_64，只能 arm64；`universal-apple-darwin` 构建会失败。
7. **TCC 权限归属**：相机/麦克风提示会落到 `com.tencent.TMSDKHelper`（显示「网络会议」），不是 YX，需产品接受。
8. **主线程/事件循环**：SDK 的 Qt/AppKit 窗口需要主 run loop，Tauri command 默认在异步线程，必须 `run_on_main_thread`。
9. **SDK 版本锁定**：3.21.303（2024-05）偏旧，服务端升级后可能要求同步升级，YX 无法独立升级。
10. **UI 风格**：会议界面是腾讯原生 UI，不是 YX 风格；若产品要求自绘，成本回到方案 D。

## 6. 建议的落地路径

1. **先花 1–2 天做 P0 spike**（不写业务代码）：
   - 从 DMG 拷 `TMSDK.framework` 到 `src-tauri/vendor/`（加 `.gitignore`，用脚本同步）。
   - `build.rs` + `cc` 编 `wemeet_shim.cc`，链接 `-F vendor -framework TMSDK`。
   - `bundle.macOS.frameworks: ["TMSDK.framework"]` + `hardenedRuntime: false` + `infoPlist` 相机/麦克风说明。
   - 一个 `#[tauri::command] wemeet_spike()`：主线程 `GetWemeetSDKInstance()->Initialize(...)` + `ShowPreMeetingView("0")`。
   - 用真实账号验证 `/v1/tencent/meeting/config` 是否放行。
2. **spike 通过** → 按 P1 做「加入会议」最小闭环（会议 Tab + 入会 + 退出）。
3. **P2 再接 IM 邀请卡片**（YX 已有 99/type5 渲染，只需补 `[JoinWeMeet]` 路由）。
4. **若授权/接口不确定** → 先上方案 C（委托官方客户端）做兜底，再评估 A。
