# 腾讯会议会中/会前「邀请」按钮接管方案

> **决策（2026-11-24）：暂不实施。** 评估后认为增量收益有限——我们的邀请主通道已经是
> IM（15 + 99），接管主要多出「会中原生入口也能选越秀通讯录」和「补上非 YX 发起的
> 会议号」；代价是 `show=false` 会同时关掉复制链接、PSTN、Rooms 等原生入口，且企业
> 若已把组织架构同步到腾讯会议，选人环节的收益更小。会前入口我们本来就不走腾讯
> 「预定会议」页。接口结论与改法保留在本文，后续需求变化时可直接复用。
>
> 适用分支：`spike/wemeet-p0`；SDK：TMSDK 3.21.303（`src-tauri/vendor/TMSDK.framework`）。
> 相关文档：[`腾讯会议邀请联调手册.md`](./腾讯会议邀请联调手册.md)（卡片/弹窗/响铃验证）、
> [`腾讯会议P0验证记录.md`](./腾讯会议P0验证记录.md)（P0–P3 结论）。

---

## 1. 结论

可以接管，TMSDK 提供了三组官方接口，分别对应三个入口：

| 入口 | 开启接口 | 回调 | 回调参数 | 我们的动作 |
| --- | --- | --- | --- | --- |
| 会中工具栏「邀请」 | `IInMeetingService::EnableInviteCallback(enable, show)` | `IInMeetingCallback::OnInviteMeeting` | `invite_info`（JSON 字符串） | 弹 YX 选人面板，走 IM 发 15 + 99 |
| 会中成员列表「添加成员」 | `IInMeetingService::EnableInviteUsersCallback(enable, show)` | `IInMeetingCallback::OnInviteUsers` | `{ users, user_type }` | 同上（`user_type=3` 成员、`4` PSTN 呼叫） |
| SDK「预定会议」页通讯录选人 | `IPreMeetingService::EnableAddressBookCallback(enable, show)` | `IPreMeetingCallback::OnShowAddressBook` | `user_type` + 通讯录 JSON | 选完必须用 `TMSDK::AddUsersWithParam` 回写 |

`enable` / `show` 的语义（官方接口文档）：

- `enable`：是否走回调。开启后点击按钮会回调宿主，而不是只弹 SDK 自己的页面。
- `show`：是否**同时**显示 SDK 自己的邀请页。`enable=false` 时 `show` 被强制为 `true`。
- 因此「完全接管」= `(true, false)`；「并存验证」= `(true, true)`；「保持原样」= 不调用。

官方云上越秀客户端**没有调用过任何一个 `Enable*Callback`**（反查 `home.js` 只有
`OnInviteMeeting → openWemeetInvite`），说明：

1. 默认状态下 SDK 会显示腾讯原生邀请页；
2. 但 `OnInviteMeeting` 回调依然会触发（官方正是靠它弹自己的 `wemeet-invite.html`）；
3. 官方把「邀请」做成了：原生页 + 自己的邀请窗（600×450、`alwaysOnTop`，内含
   「复制会议信息」和「直接邀请参会」两个按钮）。**接管时可以直接对齐这个形态。**

## 2. 会中邀请接管（主目标）

### 2.1 事件流

```
用户点腾讯会议窗口底部「邀请」
        │
        ├─(show=true) 腾讯原生邀请页照常弹出
        └─(enable=true) InMeetingCallback::OnInviteMeeting(invite_info)
                                    │
                     shim 序列化为 wemeet-event
                                    │
                 前端 stores/wemeet.ts 解析 invite_info
                                    │
                   YX 浮层（选人）→ sendInvites(code, subject)
                                    │
                       IM 15（对方弹窗）+ 99（聊天卡片）
```

### 2.2 `invite_info` 字段（来自官方文档，与我们抓到的官方实现一致）

```json5
{
  "begin_time": 1629194320,   // 秒
  "end_time": 1629197920,     // 秒
  "create_type": 1,           // 1 普通会议，2 快速会议
  "device_dial_in_guide": "",
  "general_content": "",
  "host_name": "",
  "meeting_code": "123456789",
  "meeting_url": "https://meeting.tencent.com/dm/xxx",
  "password": "",
  "mstn": "",
  "meeting_pstn_json": "",
  "subject": "会议主题",
  "participate_id": ""
}
```

要点：

- `meeting_code` 是会中邀请**唯一可信的会议号**，不要用 `store.meetingCode`（可能为空或过期）。
- `subject` 是会议主题。官方会中邀请发 15 时 `title=subject`、99 卡片「会议标题」也是
  `subject`，**不是**「XX发起的视频会议」。当前 `sendInvites` 固定用
  `${meName}发起的视频会议`，接管时需要把标题作为参数传进去。
- `begin_time` / `end_time` 是**秒**，JS 里要 `* 1000`。

### 2.3 原生层：`src-tauri/wemeet/wemeet_shim.cc`

新增一个进程级模式（`off` / `coexist` / `takeover`）并保存到全局，在「初始化结果回调之后、登录之前」下发，
对应官方文档「该接口入会之前设置有效，建议初始化回调之后，登录之前设置」。

```cpp
namespace {
// 0=不动（原生页） 1=(true,true) 并存 2=(true,false) 完全接管
int g_invite_mode = 0;

void apply_invite_mode() {
  if (!g_sdk) return;
  auto* in = g_sdk->GetInMeetingService();
  if (!in) return;
  switch (g_invite_mode) {
    case 1: in->EnableInviteCallback(true, true);  break;
    case 2: in->EnableInviteCallback(true, false); break;
    default: break;  // 不调用 = SDK 默认行为
  }
}
}  // namespace

// SdkCallback::OnSDKInitializeResult 里，wire_services() 之后补一行
void SdkCallback::OnSDKInitializeResult(int code, const char* msg) {
  emit_event("OnSDKInitializeResult", code, msg, "SDKService");
  if (code == 0 || code == kTMSDKErrorDuplicateInitCall) {
    wire_services();
    apply_invite_mode();   // 此时 Service 已可调用
  }
}

// 登录前再下发一次，避免 SDK 在 Init→Login 之间重置设置
int yx_wemeet_login(const char* sso_url) {
  /* ... */
  wire_services();
  apply_invite_mode();
  account->Login(sso_url ? sso_url : "");
  return 0;
}

int yx_wemeet_set_invite_mode(int mode) {
  g_invite_mode = (mode >= 0 && mode <= 2) ? mode : 0;
  if (!g_sdk) return 0;          // 尚未初始化：记下来，Init 回调时生效
  apply_invite_mode();
  return 0;
}
```

`OnInviteMeeting` 已经在 `InMeetingCallback` 里把 `invite_info` 原样放进 `param`，无需改动；
`emit_event` 会做 JSON 转义，前端拿到的是**字符串**，需要再 `JSON.parse` 一次。

可选增强（本期不做）：`EnableInviteUsersCallback(true, true)` + `EnableAddressBookCallback(true, true)`，
回调直接进事件面板，先观察参数结构，再决定是否接 UI。

### 2.4 头文件与 Rust 命令

`wemeet_shim.h`：

```c
int yx_wemeet_set_invite_mode(int mode);
```

`src-tauri/src/wemeet.rs`：

```rust
unsafe extern "C" {
    fn yx_wemeet_set_invite_mode(mode: i32) -> i32;
}

/// mode: "off" | "coexist" | "takeover"
#[tauri::command]
pub async fn wemeet_set_invite_mode(app: AppHandle, mode: String) -> Result<(), String> {
    let mode = match mode.as_str() {
        "coexist" => 1,
        "takeover" => 2,
        _ => 0,
    };
    let rc = call_main(&app, Duration::from_secs(3), move || unsafe {
        yx_wemeet_set_invite_mode(mode)
    })?;
    check(rc, "设置会中邀请回调")
}
```

`lib.rs` 的 `generate_handler!` 里加 `wemeet::wemeet_set_invite_mode`。

### 2.5 前端

**a) `src/services/wemeet.ts`**：照现有命令的写法加一层 `invoke` 封装。

```ts
export type WeMeetInviteMode = 'off' | 'coexist' | 'takeover'

export function wemeetSetInviteMode(mode: WeMeetInviteMode) {
  return invoke('wemeet_set_invite_mode', { mode })
}
```

**b) `src/stores/wemeet.ts`**：

- 新增状态 `inviteMode`（localStorage `wemeet_invite_mode`，默认 `off`，联调通过后再改默认值）；
- `ensureReady()` 末尾与 `setRingEnabled` 并列下发一次 `wemeetSetInviteMode(inviteMode.value)`；
- 事件分流新增：

```ts
const inMeetingInvite = ref<InMeetingInvite | null>(null)

case 'OnInviteMeeting': {
  if (inviteMode.value === 'off') break   // 保持原生页，事件只留在诊断面板
  const parsed = parseInviteInfo(e.param)
  if (parsed) inMeetingInvite.value = parsed  // 同一会议重复点击只刷新字段
  break
}
```

```ts
interface InMeetingInvite {
  code: string
  subject: string
  beginTime: number
  endTime: number
  meetingUrl: string
  password: string
}

function parseInviteInfo(raw?: string): InMeetingInvite | null {
  try {
    const j = JSON.parse(raw || '{}')
    const code = String(j.meeting_code || '').trim()
    if (!code) return null
    return {
      code,
      // 主题为空时退回「当前会议」，不要生成新标题覆盖会议上下文
      subject: String(j.subject || '').trim() || '当前会议',
      beginTime: Number(j.begin_time || 0) * 1000,
      endTime: Number(j.end_time || 0) * 1000,
      meetingUrl: String(j.meeting_url || ''),
      password: String(j.password || ''),
    }
  } catch {
    return null
  }
}
```

- 把 `sendInvites` 的标题参数化，供「发起会议」和「会中邀请」共用：

```ts
function sendInvites(invitees, code, title = `${displayName()}发起的视频会议`) { /* ... */ }

function inviteByCode(code: string, title: string, invitees) {
  return sendInvites(invitees, code, title)
}
```

- 确认/取消：

```ts
async function confirmInMeetingInvite(invitees) {
  const invite = inMeetingInvite.value
  if (!invite) return 0
  const sent = inviteByCode(invite.code, invite.subject, invitees)
  inMeetingInvite.value = null      // 发送成功才关；抛错时保留，便于重试
  return sent
}
```

**c) 面板组件**：`src/components/MeetingInvitePanel.vue`

- 结构直接复用「会议」页的 `MemberPicker`（`source="contacts"`），顶部显示
  `invite.subject`、`invite.code`、`invite.beginTime`；
- 挂在 `App.vue`（和 `MeetingInvitePrompt.vue` 同级），`v-if="wemeet.inMeetingInvite"`；
- 点「发送邀请」→ `wemeet.confirmInMeetingInvite(picked)`；
- 点「取消」→ `wemeet.inMeetingInvite = null`。

**d) 可见性（容易漏掉的一步）**

腾讯会议窗口在会中通常盖住 YX 主窗口，只弹主窗口内的浮层用户看不到。两个方案：

- **MVP（推荐先做）**：打开面板时 `getCurrentWindow().setAlwaysOnTop(true)` + `setFocus()`，
  关闭后恢复 `setAlwaysOnTop(false)`。改动小，够用。
- **对齐官方**：用 `WebviewWindowBuilder` 新开 `wemeet-invite` 窗口（600×450、`alwaysOnTop`、
  标题「会议号：xxx」），路由 `#/wemeet-invite`。代价是新窗口没有 IM 长连接，
  选完人要 `emitTo('main', 'wemeet-invite-confirm', picked)` 回到主窗口发送；
  联系人数据也要解决跨 webview 的 localStorage 一致性。除非 MVP 被全屏会议挡住，不建议一上来就做。

### 2.6 联调开关

`WemeetView.vue` 的「连接状态」区加一个三选一（与「响铃邀请」并列）：

| 选项 | 下发 | 表现 | 用途 |
| --- | --- | --- | --- |
| 不接管（默认） | 不调用 | 只有腾讯原生邀请页 | 当前线上行为，零风险 |
| 并存 | `(true, true)` | 原生页 + YX 面板同时出现 | 首次联调，确认 invite_info 与发送链路 |
| 接管 | `(true, false)` | 只有 YX 面板 | 验证通过后的正式形态 |

## 3. 会中成员列表「添加成员」（可选）

`EnableInviteUsersCallback(true, false)` → `OnInviteUsers`：

```json5
{ "users": ["u1", "u2"], "user_type": 3 }   // 3=成员邀请，4=PSTN 呼叫
```

- `user_type=3`：弹 YX 选人面板，只发 IM 15 + 99，**不要**调用 `AddUsersWithParam`。
  因为 YX 的 `user_id` 是越秀账号体系，腾讯侧不认识，硬调只会得到
  `-2005`（uid 为空）或无效邀请回调；官方同样没有把两套账号打通。
- `user_type=4`（PSTN 电话呼叫）：一旦 `show=false`，SDK 的电话拨号页会被关掉。
  这是接管成员列表最实际的损失，因此本项目**不接管这一项**，保持 `show=true` 或不开启。

结论：`EnableInviteUsersCallback` 默认不开；如果要做，只开 `(true, true)` 并存，不做全量替换。

## 4. 会前「邀请」：先分清两种含义

### 4.1 YX 自己的会前入口（已完成，不涉及 SDK 回调）

- 聊天顶部「视频会议」：单聊直邀、群聊选人；
- 会议页「邀请同事」；
- 两者都是「先快速会议拿会议号，再发 15 + 99」，见 `stores/wemeet.ts` 的
  `startMeetingAndInvite` / `inviteToMeeting`。

这部分没有腾讯原生按钮，**不需要接管**。

### 4.2 SDK「预定会议」页的通讯录选人（可选，低优先级）

只有用户真的在腾讯原生「预定会议」页点通讯录时才有意义：

```cpp
pre->EnableAddressBookCallback(true, false);
```

`OnShowAddressBook(user_type, json_data)` 的 `user_type`：`1` = 设置主持人，`2` = 添加成员。
宿主弹出自己的通讯录，选完后**必须**回写，否则预定会议里看不到人：

```cpp
// users 必须是客户侧账号体系里的 id
std::string json = R"({"users":["u1","u2"],"user_type":2})";
g_sdk->AddUsersWithParam(json.c_str());
```

结果通过 `ISDKCallback::OnAddUsersResult(user_type, code, msg)` 回调（当前 `SdkCallback`
没有覆盖它，需要补一个 override 转成事件）。

限制与结论：

- 只对 SDK 自己的「预定会议」界面生效，我们的快速会议/自定义页面用不上；
- 必须回写 `AddUsersWithParam`，否则只是「选了个寂寞」；
- 官方没有启用，我们默认也不启用。等真正需要「在腾讯界面里预定会议并邀请同事」时再做，
  工作量与风险都高于会中接管。

## 5. 实施顺序（建议）

1. **0 改动验证**：会议中点原生「邀请」，看事件面板是否出现 `OnInviteMeeting`
   （官方没调 `Enable*` 也能收到，我们 shim 已注册回调，理论上同样能收到）。
   - 有：进入第 2 步；
   - 没有：先只加 `EnableInviteCallback(true, true)`，确认回调出现。
2. **并存模式跑通链路**：`(true, true)` + YX 面板 + 选人发送，确认对方收到 15（弹窗）和 99（卡片），
   会议号与主题取自 `invite_info`。
3. **切完全接管**：`(true, false)`，确认原生邀请页不再出现，且「复制链接 / PSTN / Rooms」
   等入口消失是产品可接受的。
4. 把 `inviteMode` 默认值从 `off` 改成 `takeover`（或按企业配置），文档与 README 同步。

## 6. 验证清单（双账号）

| 步骤 | 预期 |
| --- | --- |
| A 入会，点腾讯窗口底部「邀请」（并存模式） | 原生页出现，同时 YX 弹邀请面板；事件面板出现 `OnInviteMeeting`，`param` 含 `meeting_code` / `subject` |
| YX 面板选 1 人发送 | 对方弹「邀请您加入视频会议」，聊天里一张会议卡片；卡片会议号与原生页一致 |
| 切「接管」后再点「邀请」 | 只出现 YX 面板，无腾讯原生页 |
| 同一会议连点两次「邀请」 | 面板只刷新，不叠加 |
| 会议号为空 / 解析失败 | 面板不弹，事件面板显示原始 `param`，便于定位字段变化 |
| 邀请后立刻退会 | 已发出的 IM 邀请不受影响，面板自动关闭 |
| 关闭「接管」 | 恢复腾讯原生邀请页，YX 不再弹面板 |

## 7. 风险与边界

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| `show=false` 不生效 | SDK 版本行为可能和文档不一致，原生页仍出现 | 先并存验证；不生效就保持 `(true, true)`，把「接管」当增强项 |
| 丢掉腾讯入口 | 完全接管后，复制会议链接、PSTN、Rooms 呼叫等会一起消失 | 产品确认；或在 YX 面板里补「复制会议信息」按钮（官方邀请窗就有） |
| 回调时序 | 文档要求「入会前设置」，登录后再设置可能无效 | 在 `OnSDKInitializeResult` 与 `login` 前各下发一次 |
| 多窗口 / 全屏 | 腾讯会议全屏时主窗口浮层不可见 | MVP 用 `setAlwaysOnTop(true)`；不行再走独立窗口 |
| `invite_info` 字段变化 | 不同版本可能增删字段 | 解析时全部做兜底，解析失败只在事件面板展示原文 |
| 用户 id 体系不通 | `OnInviteUsers` 的 users 是腾讯侧 id，与越秀账号无关 | 只发 IM，不调 `AddUsersWithParam(user_type=3)` |
