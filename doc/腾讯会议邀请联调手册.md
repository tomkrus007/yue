# 腾讯会议邀请联调手册（P2/P3）

> 适用分支：`spike/wemeet-p0`；客户端版本：`YX 0.1.23` + TMSDK 3.21.303（官方 5.2.97）。
> 覆盖：**邀请卡片**、**全局邀请弹窗**、**响铃邀请**，以及 P3 的按账号缓存。
> 代码行为以当前 `src/services/im/wemeet-invite.ts`、`src/stores/wemeet.ts` 为准。

---

## 1. 覆盖范围

| 能力 | 入口 | 当前实现 |
| --- | --- | --- |
| 邀请卡片 | 聊天时间线 / 历史 | 15（`[OpenApp] appCode=linkMeeting`）与 99（`type 3` + `[JoinWeMeet]`）都归一化成会议卡片；同人同号 10 分钟内的 99 去重 |
| 全局弹窗 | App 根组件 | 实时收到 15 时弹「视频会议邀请」；离线/超过 10 分钟/会议中/自己发的都不弹 |
| 响铃邀请 | TMSDK 原生 | 登录后 `EnableRingInvitationView(true)`，SDK 自绘接听窗；会议页可关闭 |
| 发起邀请 | 聊天顶部「视频会议」/ 会议页「邀请同事」 | 快速会议 → `OnJoinMeeting.code=0` 拿会议号 → 每人发 15 + 99 |
| 缓存隔离 | 登录/退出登录 | `~/Library/Caches/com.tom.YX/{Uid}/wemeet_cache`，退出登录后删除 |

## 2. 环境准备

### 2.1 角色

| 角色 | 客户端 | 用途 |
| --- | --- | --- |
| A | 本仓库 `pnpm tauri build --debug` 产出的 `YX.app` | 被验证方 |
| B | 官方 `云上越秀.app`（`yx-packages/` 里的 DMG） | 发起/接收，基准行为 |

- A、B 必须是**两个不同账号**，且互为好友、有单聊。
- 不要同时开两个 YX：两者共用 `com.tom.YX` 的 localStorage（登录态），而且没有 single-instance 保护。
- 一台 Mac 可以同时跑 `YX.app` 和官方客户端（bundle id 不同）；如果 IM 登录互相挤掉，改用两台机器。

### 2.2 构建与启动

```bash
cd YX
./scripts/sync-wemeet.sh        # 已有 src-tauri/vendor/TMSDK.framework 可跳过
pnpm tauri build --debug
open src-tauri/target/debug/bundle/macos/YX.app
```

- **不要用 `pnpm tauri dev`**：TMSDK 依赖 `.app` 的 `CFBundleIdentifier`，裸二进制会直接崩。
- 首次入会会申请摄像头/麦克风权限，先各点一次允许，避免把权限弹窗误判成故障。

### 2.3 联调前检查

1. A 打开左侧「会议」→ 点一次「打开会前界面」→ 状态变成「已就绪」。
   TMSDK 是懒加载，首次操作才初始化；不初始化时收不到响铃，邀请回调也不可用。
2. A、B 都确认 IM 在线（互发一条文本能收到）。
3. A 的会议页「响铃邀请」开关保持默认开启。

## 3. 行为速查

| 场景 | 对方发来的消息 | A（YX）表现 |
| --- | --- | --- |
| 官方主动邀请 | 15 + 99（官方 `joinWeMeetCallback`） | 立即弹窗；时间线**一张**会议卡片（99 被去重） |
| 官方「分享到聊天」 | 只有 99 | 不弹窗；时间线一张会议卡片 |
| YX 主动邀请 | 15 + 99 | 接收方：弹窗 + 一张卡片；发送方：自己会话里一张卡片 |
| 离线补发 | 15（`offline=true`） | 不弹窗；有卡片 |
| 超过 10 分钟的邀请 | 15 | 不弹窗；有卡片 |
| 已在会议中 | 15 | 不弹窗；有卡片 |
| 响铃邀请 | TMSDK 通道（不是 IM） | SDK 自绘接听窗；事件面板出现 `OnRingInvitationEvent` |

## 4. 用例

### 4.1 用例 A：官方 → YX（卡片 + 弹窗）

1. B 在官方客户端与 A 的单聊，点顶部「视频会议」，按弹窗选 A，发起。
2. 观察 A：

| 检查点 | 通过标准 |
| --- | --- |
| 全局弹窗 | 立即出现「视频会议邀请」，显示发起人、会议标题、会议号 |
| 时间线卡片 | 只有**一张**会议卡片（不是 15 和 99 两张） |
| 卡片内容 | 标题、会议号、`加入会议` 按钮可点 |
| 入会 | 点「加入会议」能进入会前/会中界面，显示名是 A 的用户名 |
| 稍后 | 点「稍后」弹窗关闭，卡片仍在，可再次入会 |

3. 失败排查：
   - 没弹窗但有卡片 → A 当时不在线（`offline=true`）、超过 10 分钟、已在会议中，或消息被去重逻辑吞掉（检查 `from_id`/会议号）。
   - 两张卡片 → `dedupeMeetingCards` 未命中：两条消息的 `from_id` 或 `meetingCode` 不一致，或时间差超过 10 分钟。
   - 弹窗显示「加入会议失败」 → 看会议页事件面板的 `OnJoinMeeting` 错误码。

### 4.2 用例 B：YX → 官方

1. A 在 YX 与 B 的单聊，点顶部「视频会议」。
2. 预期：

| 检查点 | 通过标准 |
| --- | --- |
| 发起 | 首次等 3–10 秒；成功后提示「会议已开始，已向 1 人发送邀请」 |
| 官方弹窗 | B 出现「A 邀请您加入视频会议」 |
| 官方卡片 | B 的聊天里有一张会议卡片（99），关掉弹窗仍可回看、加入 |
| 入会 | B 点加入后与 A 在同一会议（互相看到对方） |
| 群聊邀请 | A 在群聊点「视频会议」→ 先选人 → 只有选中的人收到弹窗 |
| 会议页邀请 | A 在「会议」页点「邀请同事」→ 选人 → 同样收到 15 + 99 |

3. 失败排查：
   - 提示「还没有会议号」→ 先发起会议再邀请；或 `OnJoinMeeting` 未拿到号。
   - 官方没弹窗 → B 是否在线、是否好友、A/B 是否同一企业 IM。
   - 官方有弹窗没卡片 → 99 发送失败（连接中断），事件面板/日志里应有发送失败记录。

### 4.3 边界用例

| 操作 | 通过标准 |
| --- | --- |
| A 退出 YX → B 发邀请 → A 重新登录 | 只有卡片，没有弹窗（离线补发） |
| 邀请发出 10 分钟后 A 才重新连上 | 只有卡片，没有弹窗 |
| A 在会议中，B 再发邀请 | 不弹窗，卡片照常 |
| A 自己给自己发邀请（用官方 B 账号模拟不了则跳过） | 不弹窗 |
| 同一会议被官方连续邀请两次 | 每张 15 都有卡片；不出现重复 99 卡片 |

### 4.4 用例 C：响铃邀请

**前置条件（缺一不可）**

1. A 的会议组件已初始化并登录（会议页显示「已就绪」）；
2. 「响铃邀请」开关是开的；
3. 存在一个能主动响铃的发起端。

**为什么发起端难找**：官方越秀客户端没有启用 TMSDK 响铃（反查 `home.js` 只有 `OnInviteMeeting`，没有 `EnableRingInvitationView`），YX 的邀请统一走 IM。可行路径：

- B 在腾讯会议原生会前/会中窗口点「邀请」，看是否有「响铃 / 电话提醒」选项；
- 或在另一台设备用腾讯会议企业版客户端登录同企业账号，从通讯录邀请 A 并勾选响铃。

**步骤与预期**

| 步骤 | 通过标准 |
| --- | --- |
| 发起端对 A 发起响铃 | A 弹出**腾讯会议自绘**的接听窗口（不是 YX 的弹窗） |
| A 点接听 | 直接进入会议，B 能看到 A |
| A 点拒绝/不处理 | 窗口关闭；事件面板出现 `OnRingInvitationEvent` |
| 关闭会议页「响铃邀请」后再发 | 不再弹原生窗（IM 邀请仍可用） |

**判定**：如果连 `OnRingInvitationEvent` 都没有，说明没有发起端或企业未开通响铃，记为「未联调」，不阻塞验收；如果事件有但窗口不弹，记录 `ring_state` 和 `param`，属于 SDK 行为问题。

## 5. 观察点

| 位置 | 用途 |
| --- | --- |
| 会议页「原生事件」 | 所有 SDK 回调：`OnJoinMeeting`、`OnInviteMeeting`、`OnRingInvitationEvent`、错误码 |
| 会议页「连接状态」 | 组件是否就绪、当前会议号、响铃开关 |
| 聊天时间线 | 15/99 卡片、去重结果 |
| 缓存目录 | `ls ~/Library/Caches/com.tom.YX`，发起过会议后应有 `{Uid}/wemeet_cache`；退出登录后 `{Uid}` 消失 |
| 进程 | `pgrep -fl TMSDKHelper`，确认原生辅助进程在跑 |
| 应用日志面板 | IM 连接、消息发送失败、HTTP 错误（会脱敏地址） |

## 7. 已知限制

- 去重只在聊天时间线（`ChatView`）和历史弹窗（`HistoryModal`）生效；合并转发详情、收藏等视图仍按原始消息展示。
- 响铃依赖 SDK 已初始化（懒加载），冷启动后未用过会议时收不到响铃。
- 会中/会前「邀请」按钮目前仍是腾讯原生 UI，接管方案见
  [`腾讯会议邀请按钮接管方案.md`](./腾讯会议邀请按钮接管方案.md)。
- 联调需要真实越秀生产账号 + 腾讯会议企业授权，仓库没有测试账号。
