> 分析目标：复刻 IM 通信功能 与 网盘（云盘）调用功能
> 分析方式：REA 静态分析 + 源码直查（应用为解包 Electron 工程，JS 未加密）
> 应用版本：5.2.97 (CFBundleVersion 161)，Bundle ID `com.bingo.linkyuexiu`
> 厂商：品高软件 Bingosoft（BingoLink / PCLink 平台），域名 bingolink.biz / yuexiu.com

## 一、总体架构

应用本质是 **品高 BingoLink（PCLink）桌面端** 为越秀集团做的定制打包，基于 Electron + Atom 壳。

```
云上越秀.app
├─ Contents/MacOS/云上越秀              # Electron 主进程入口
├─ Contents/Frameworks/
│  ├─ Electron Framework.framework     # Electron 内核
│  ├─ libnemoSDK.dylib                 # 小鱼易联(xylink) 视频会议 SDK（非 IM，可忽略）
│  ├─ libxylinkAIEngine.dylib          # 音视频 AI 引擎
│  ├─ TMSDK.framework                  # TrustMobile 安全 SDK（零信任相关，非 IM）
│  ├─ Mantle/ReactiveObjC/Squirrel     # macOS 通用框架
│  └─ libav* / libfdk-aac / libswscale # FFmpeg 音视频编解码
└─ Contents/Resources/app/             # 应用业务代码（未 asar 打包，明文 JS）
   ├─ package.json                     # 依赖：ws / google-protobuf / sqlcipher / request …
   ├─ main.js                          # Electron 入口
   ├─ src/                             # 主进程层（Electron Main / Preload）
   │  ├─ App.js                        # 应用生命周期、窗口调度
   │  ├─ MainProcess.js                # 主进程 API（窗口/IPC/原生能力）
   │  ├─ RenderProcess.js              # 渲染进程 API 桥（ipcRenderer 通道）
   │  └─ plugins/
   │     ├─ file/fileserver.node       # 网盘本地服务（PC 端 HTTP/WS 服务）
   │     ├─ addon/fsdes.node           # 文件系统扩展（虚拟盘）
   │     ├─ HttpServer.js              # 本地 HTTP 服务
   │     ├─ PortUtil.js                # 本地端口分配
   │     ├─ wemeet/                    # 腾讯会议 SDK
   │     ├─ calendar/                  # 日历集成
   │     └─ TrustAgent_yuexiu_*.sdk.pkg # 越秀零信任客户端
   └─ web/                             # 渲染层（Web 前端）
      ├─ config.json                   # ★ 主配置（含所有服务端点）
      ├─ linkplugin.js                 # ★ 第三方集成 JS SDK（IM/网盘高层 API）
      ├─ main.js / vue.min.js          # 主面板入口
      ├─ html/                         # IM 主面板 + 各功能页（webpack 打包）
      │  └─ static/js/home.<hash>.js   # 主 IM bundle（压缩）
      ├─ disk/                         # ★ 网盘前端（独立 AngularJS 应用）
      │  ├─ config.json                # 网盘配置
      │  └─ html/app/                  # 网盘 UI + service 层
      └─ plugins/
         ├─ minfs/                     # S3 虚拟盘挂载（minfs 二进制）
         ├─ ftpfs/                     # FTP 文件系统
         ├─ ocr/ zta/ zte/             # OCR / 零信任
```

### 关键技术栈
- **运行时**：Electron（`AtomApplication`），渲染进程跑 Vue + jQuery + requirejs/seajs
- **IM 通信**：WebSocket + Protobuf（`ws`、`google-protobuf`）
- **本地存储**：SQLCipher 加密 SQLite（`@journeyapps/sqlcipher`）
- **网盘**：REST + WebSocket（在线编辑用 WS 通道），本地通过 `fileserver.node` 起 HTTP/WS 微服务
- **加密**：RSA（登录密码）/ SM2（国密可选）/ AES（数据）；登录用 RSA 公钥加密密码

## 三、IM 通信功能详解

### 3.1 传输层
- **协议**：WebSocket（默认 `ws://msg.bingolink.biz:10083`，明文 ws；NSAllowsArbitraryLoads=true）
- **消息编码**：Google Protobuf（`google-protobuf ^3.15.1`）
- **心跳/重连**：主进程 `ws` 模块负责长连，渲染层通过 IPC 接收推送

### 3.2 IM 客户端代码位置
- 主进程侧：`src/MainProcess.js` / `RenderProcess.js` 通过 `ipcRenderer.send('NativeApiOnMain', {...})` 与原生层通信
- 业务侧：`web/html/static/js/home.<hash>.js`（webpack bundle，压缩）—— 包含会话列表、聊天、消息收发逻辑
- 历史消息：`web/html/historyMsg.html` + `historyMsg.<hash>.js`
- 聊天窗口：`html/chat.html`（旧版）/ 主面板内嵌（新版）

### 3.3 消息模型（来自 linkplugin.js 文档注释）
消息类型 `msgType` 参考品高文档：`http://dev.bingocc.com/im/msg/text.html`

会话/对象类型 `type`：
| 值 | 含义 |
|---|---|
| 1 | 用户（单聊） |
| 2 | 群组 |
| 4 | 部门 |
| 5 | 服务号 |
| 9 | AI 机器人 |
| 13 | 用户标签 |
| 14 | 事务/项目 |

消息体 `msgInfo`：`{ msgType, content }`，msgType 含文本、图片、文件、项目卡片(11)、AI 等。

### 3.4 IM 高层 API（来自 `linkplugin.js`，可直接复刻的接口契约）

```js
// 发起聊天（打开会话窗口）
app.linkplugin.openChat(id, type, name, callback)
// id: 数据id；type: 1用户/2群组/4部门/5服务号；name: 显示名

// 发送消息（以当前登录用户身份）
app.linkplugin.sendMsg(targetObj, msgInfo)
// targetObj: { id, name, type, eCode }
// msgInfo:   { msgType, content }   // 参考 dev.bingocc.com/im/msg/text.html

// 监听消息通知
app.linkplugin.listenMessage(appCode, callback)
// callback(info): info = { action, params }
//   action: TabActive | MessageAction | Message
//   需先调 registerListenSession 注册要监听的会话

app.linkplugin.registerListenSession(appCode, sessionIds)

// 获取最近联系人
app.linkplugin.getRecentContacts(callback, needGroup, needOrg)

// 解密消息（IM 消息体加密存储）
app.linkplugin.decryptMsgs(msgs, success, error)

// 获取/刷新 AccessToken
app.linkplugin.getAccessToken(callback)
app.linkplugin.refreshToken(callback)

// 获取当前用户信息
app.linkplugin.getUserInfo(callback)
```

底层桥接：上述 API 通过 `app.trigger('ProxySendChatMsg', [...])` / `app.listen('WidgetMessage'+appCode, ...)` 走 IPC 到主进程，主进程再走 WebSocket/Protobuf 与 `msg.bingolink.biz:10083` 通信。

### 3.5 复刻 IM 的最小实现建议
1. **登录**：POST `{ssoUrl}/oauth/token`（grant_type=password，client_id=link_desktop，RSA 加密密码）拿 AccessToken
2. **建连**：`new WebSocket('ws://msg.bingolink.biz:10083')`，握手时携带 AccessToken 鉴权
3. **协议**：用 protobuf 定义 `Message`/`Session`/`Notification` 等结构（需进一步抓包/反编译 home.js bundle 还原 .proto 文件——见下方"待办"）
4. **能力**：单聊/群聊收发文本、文件（与网盘联动）、消息加密（AES）、未读数、心跳重连

> 还原完整 .proto schema 与 cmdId 对照表需对 `home.<hash>.js` 做更深的反混淆分析，或运行期抓包（WebSocket frame）。

## 四、网盘（云盘）调用功能详解

### 4.1 架构
网盘是**独立的 BingoCloudDisk AngularJS 应用**，挂在主面板 "DiskTabView" 下。三层结构：

```
渲染层 (web/disk/html/app/)  ──HTTP/WS──>  本地 PC 服务 (fileserver.node, 127.0.0.1:pc_port)
                                              │
                                              ├──（代理/直连）──> 远端 pan.bingolink.biz/openapi
                                              └──（流式）──────> pan.bingolink.biz/stream
```

- 本地 `pc_port` / `sync_port` 由 `src/plugins/PortUtil.js` 动态分配，存 localStorage
- 本地服务由 `src/plugins/file/fileserver.node`（原生 Node Addon）提供，负责：上传/下载断点续传、虚拟盘（minfs）、同步盘
- 在线编辑（WPS）走 WebSocket：`ws://<streamEndpoint>/v1/file/open?Authorization=Bearer <token>&fileId=<id>`

### 4.2 认证（`disk/html/app/ajaxSetting.js`）
所有请求 `$.ajaxSetup` 注入：
```http
Authorization: Bearer <auth_accessToken>
appId: <APP_ID>          # BingoCloudDisk
x-forwarded-for: <IP>
x-real-ip: <IP>
Accept-Language: <langForApi>
X-Requested-With: XMLHttpRequest
```
401 时 `ssoService.refreshAccessToken()` 刷新令牌后重试。

### 4.3 文件 REST API（`disk/html/app/common/services/fileService.js`）
基址 `CONFIG.WEBAPI_ENDPOINT`（即 `https://panbeta.bingolink.biz/openapi`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/file/info` | 文件详情 |
| POST | `/file/batchInfo` | 批量详情 |
| GET | `/file/list` | 列目录（orders: [{by:'type'}]） |
| GET | `/file/chain` | 路径链 |
| GET | `/file/check_dir_name` | 校验目录名 |
| POST | `/file/mkdirs` | 创建目录 |
| POST | `/file/move` | 移动 |
| POST | `/file/delete` | 删除 |
| POST | `/file/copy` | 复制 |
| GET | `/file/search` | 搜索 |
| POST | `/file/lock` | 锁定 |

其它 service：`fileShareService`（分享）、`fileTrashService`（回收站）、`folderAuthorityService`（权限）、`quotaService`（配额）、`teamService`/`orgService`/`publicService`（团队/部门/公开文档）、`syncService`（同步盘）、`tqueueService`（转码队列）、`reviewService`（评审）。

### 4.4 网盘高层 API（`linkplugin.js`，复刻集成接口）


## 五、复刻建议（聚焦 IM + 网盘）

### 5.1 推荐技术选型
- **壳**：Electron（保持一致）或任意跨端框架
- **IM**：Node.js `ws` + `protobufjs`；后端可对接 BingoLink IM 或自建兼容服务
- **网盘**：HTTP 客户端（axios/fetch），按上述 REST 契约调用 `pan.bingolink.biz/openapi`
- **存储**：SQLCipher 本地加密（会话/消息缓存）

### 5.2 复刻优先级
1. **登录鉴权**：实现 OAuth2 + RSA 密码加密 → 拿 AccessToken（IM 与网盘共用）
2. **IM 连接**：WebSocket 连 `msg.bingolink.biz:10083`，实现心跳/重连/protobuf 编解码
3. **IM 会话**：单聊、群聊、消息收发、未读数、历史消息拉取
4. **网盘基础**：文件列表/详情/上传/下载/删除/移动/复制
5. **网盘增强**：分享、权限、回收站、同步盘、在线编辑（WS）

### 5.3 风险与未知项
- **Protobuf schema 未完整还原**：`home.<hash>.js` 为压缩 webpack bundle，IM 消息的 cmdId / 字段定义需进一步反混淆或抓包还原
- **服务端可达性**：`bingolink.biz` / `yuexiu.com` 为越秀内网/受控服务，复刻后端如不可达需自建兼容协议
- **零信任**：`zt.yuexiu.com:443` 零信任网关（TrustAgent）可能介入部分请求，复刻时若不需可绕过
- **加密消息**：IM 消息体可能 AES 加密，密钥协商逻辑在主进程 native 层，需进一步分析 `libnemoSDK`/主进程
