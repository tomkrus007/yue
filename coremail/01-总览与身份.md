## 1. 一句话结论

这是一款**"原生 C++ 邮件引擎 + wxWidgets 原生外壳 + CEF 网页视图"的混合架构桌面邮件客户端**：邮件收发、协议、本地存储、索引、加密都在 C++（`CoremailEngine`）里完成；界面大量采用内嵌 CEF 加载本地 HTML/JS 模板（`Contents/MacOS/app/template/`），只有少量窗口仍是原生 wxWidgets 控件。它同时提供**内置 AI 助手**、**本地 MCP 服务**、**本地 HTTP SDK** 三种对外开放的能力面，其中后两者是明显的"给 AI Agent 用"的设计。

## 4. 构建来源（观测，含一次信息泄露）

二进制保留了完整的 Jenkins 编译路径，可直接还原内部工程结构：

```
/Users/cm/jenkins_workspace/workspace/mac_arm_dev/
├── MailClientEngine/        # 邮件引擎（协议、存储、MIME、导入）
│   ├── protocol/            # 最多调试路径，含 imp/、socketio
│   ├── storage/             # MailStorage / MailIndex
│   ├── mime/  utils/  import/
├── CMClient/                # 客户端 GUI 层
│   ├── gui/                 # mainframe、readmail、compose、miscdlg
│   ├── guilib/              # webview_chromium3*.cpp/.mm
│   └── base/
└── 3rd/                     # wx, boost, ara, cppjieba, cef, openssl ...
```

**推断**：构建机为 `cm` 用户的 macOS arm64 Jenkins 工作区；`win3rdlib/cef/macos` 的路径说明构建系统是跨平台的（同一套工程也产出 Windows 版），CEF 依赖仍放在名为 `win3rdlib` 的目录下——典型的"目录名沿用、内容按平台分"的历史包袱。

一个值得注意的细节：调试路径中出现 `MailClientEngine/protocol/socketio_client.cpp`（272 处），说明**引擎内自带一个 Socket.IO 客户端**，用于推送/实时通道，而不是只依赖 CEF 侧 JS。

## 5. 应用包结构

```
Coremail邮箱客户端软件V4.0.app/
├── Contents/
│   ├── Info.plist
│   ├── MacOS/
│   │   ├── cmclient                      # 主二进制（109 MiB，含全部引擎+wx+部分 CEF 绑定）
│   │   ├── libgmssl.3.dylib              # GmSSL 3（软链/副本）
│   │   ├── libgmssl.3.1.dylib            # GmSSL 3.1 实体
│   │   ├── libgmssl.dylib                # 版本无关入口
│   │   └── app/                          # ★ 纯资源 + 可执行脚本目录
│   │       ├── conf/                     # 功能开关 / 私有化配置（JSON/JS）
│   │       ├── dict/                     # cppjieba 分词词典
│   │       ├── licensing/                # OSS 依赖许可清单
│   │       ├── locale/                   # ~70 种语言（.txt + .mo + mcpdef/mcp 定义）
│   │       ├── plugin/                   # IM 插件配置 + webview 桥
│   │       ├── resource/                 # 图标/CSS/声音/HTML 片段
│   │       ├── skills/                   # ★ HTTP SDK 的 TypeScript 客户端（含文档）
│   │       ├── template/                 # ★ CEF 加载的 Web UI 模板
│   │       ├── tzdata/                   # IANA 时区数据
│   │       └── userdata/CEF/User Data/   # CEF profile 种子目录
│   └── Frameworks/
│       ├── Chromium Embedded Framework.framework/   # 约 153 MiB（160 MB）
│       ├── cmclient Helper.app                       # 主进程辅助
│       ├── cmclient Helper (GPU).app
│       ├── cmclient Helper (Renderer).app
│       └── cmclient Helper (Plugin).app
```

**关键观察**：`Contents/MacOS/app/` 是一个"资源与工具混装"目录，里面既有纯数据（词典、时区），也有可直接被外部 Agent 读取的 **TypeScript 工程**（`skills/`）和 **Web UI 源码**（`template/`）。这在逆向与二次开发上意味着：**不需要反编译就能拿到相当一部分前端逻辑和对外 API 契约**。

## 6. 与同类产品的定位对比

| 维度 | 本客户端 | 典型 Electron 邮件客户端 |
|---|---|---|
| UI 技术 | wxWidgets 原生 + CEF 局部网页 | 整窗 Chromium |
| 引擎语言 | C++（自有 `CoremailEngine`） | Node/JS |
| 本地存储 | sqlite3mc（自研加密扩展）+ Xapian | SQLite + 可选 FTS |
| 加密 | 国密 SM2/SM3/SM4 + S/MIME + 自有 AES | 多为 TLS 传输层 |
| 对外能力 | 本地 HTTP SDK + 本地 MCP + AI 助手 | 少量插件 API |
| 推送 | 私有协议 + Socket.IO + EWS Push | IMAP IDLE / 厂商推送 |

这不是一个"套壳网页"应用，而是一个**重资产原生客户端**，网页层只承担阅读/写信/日历等富文本编辑场景。
