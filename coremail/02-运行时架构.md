# 运行时架构

## 1. 进程模型（观测 + 推断）

```
cmclient (主进程, wxNSApplication)
├── CoremailEngine 线程池 (ara:: 网络/日志/HTTP)
│   ├── 协议线程：IMAP / POP3 / SMTP / EWS / 私有协议
│   ├── 推送线程：socketio_client / EWS Push / 私有长连
│   ├── 存储线程：MailStorage / MailIndex(Xapian)
│   └── 本地服务：Plugin_CommandServer_Http (SDK/MCP)
├── wxWidgets 主线程（原生窗口、菜单、Ribbon、列表控件）
└── CEF 子进程
    ├── cmclient Helper.app              (browser 辅助)
    ├── cmclient Helper (Renderer).app   (每个 WebView 渲染进程)
    ├── cmclient Helper (GPU).app
    └── cmclient Helper (Plugin).app     (PPAPI/插件)
```

**观测依据**：`Frameworks/` 下 4 个 Helper.app 与标准 CEF 多进程布局一致；`cmWebViewPanel`、`webview_chromium3.cpp`、`webview_chromium3_mac.mm` 同时存在，说明 wxWidgets 侧自己封装了一层 CEF 宿主（wrapping `CefClient` / `CefLifeSpanHandler` / `CefV8Handler`），而没有用 `wxWebViewChromium` 的官方后端（二进制里 `wxWebViewChromium` 字样存在但调试路径指向自研 `guilib/webview_chromium3`）。

**推断**：`cmWebViewPanel` 是核心抽象——它把一个 CEF 浏览器实例包装成 wxWidgets 控件，并负责：
- 注册 V8 扩展（`CefRegisterExtension`）；
- 把 JS 调用转成 wx 事件 `JsCallbackEvent`，再投递到主线程（`registerJSCallback` / `registerTempJSCallback`）；
- 把原生事件回调成 JS 全局函数（`window.app.funcN`）。

## 2. 三层分工

| 层 | 技术 | 职责 | 证据 |
|---|---|---|---|
| 外壳 | wxWidgets 3.x | 主窗口、Ribbon/工具栏、文件夹树、邮件列表控件、对话框、菜单、托盘、快捷键 | `MainFrame`(853 符号)、`guiMailDetailView`(702)、`ComposePanel`(553) |
| 富内容视图 | CEF 109 + 本地 HTML/JS | 读信正文、写信编辑器、日历视图、会议预约、AI 面板、加密邮件展示 | `template/` 13 个子目录 |
| 引擎 | C++ `CoremailEngine` | 协议、账号、存储、索引、MIME、加密、日历、联系人、同步 | `CoremailEngine::MailEngine`(17k 符号)、`Protocol`(12k) |

**观察到的重要事实**：`locale/setting.en.txt` 里 `LANG_MAILLIST_ITEM` 的值是带 `<TEXT TYPE=3>`、`<FONT COLOR>`、`<FLAGS>` 自定义标记的字符串。这说明**邮件列表不是网页**，而是 wxWidgets 自绘控件（`maillist_html.cpp` / `maillist_treectrl.cpp`），用一套自制轻量富文本标记渲染。同一文件里 `LANG_SCHEDULE_*` 有 342 条、`LANG_COMPOSE_*` 294 条，与模板目录中的 `calendar/`、`compose/` 呼应。

## 3. JS ↔ 原生桥（观测，可完整还原）

### 3.1 JS 侧

`template/utils/callPC.js`（压缩后仅一行）：

```js
var callPC = function(n = "", e = {}) {
  var t = JSON.stringify(e);
  navigator.userAgent.indexOf("Chrome") !== -1
    ? window.CM(n, t)                       // CEF 环境：同步调用注入函数
    : window.CM.postMessage(n + "?" + t);   // 非 CEF 环境：postMessage 兜底
  ...
};
```

- 函数名与参数的传参方式是 **`window.CM(funcName, jsonString)`**。
- 参数统一 JSON 序列化，避免多参数签名问题。
- 有一条 `onContentChangeRes` 的特例日志抑制逻辑。

### 3.2 原生侧

- `cmWebViewPanel::onJsCallbackEvent(JsCallbackEvent&)` / `onJsCallbackEvent(std::string const&, ara::var&&)`：统一入口。
- `cmWebViewPanel::registerJSCallback(name, fn)`：常驻回调。
- `cmWebViewPanel::registerTempJSCallback(name, fn)`：一次性回调（用于请求-响应配对）。
- 回调名生成规则见 `template/lib/cmAI/cmAI.js`：`getFuncName = t => (t.match(/^app\.(.+)/) || [])[1]`，即 JS 侧传入 `"app.funcN"`，原生侧调用 `window.app.funcN(payload)`。

## 4. 插件式窗口注册

`Plugin` 命名空间下有 602 个符号，按功能族分布：

| 插件 | 符号数 | 职责 |
|---|---|---|
| `Plugin_IM` | 86 | 即时通讯入口（聊天/群聊） |
| `Plugin_Toolbar` | 43 | 工具栏按钮注入 |
| `PluginSetting` | 39 | 设置页扩展 |
| `Plugin_Status` | 28 | 状态栏 |
| `Plugin_ExtAuth` | 19 | 外部认证（CMS SOO） |
| `Plugin_MailMenu` | 17 | 邮件右键菜单 |
| `Plugin_MainEntry` | 16 | 主入口（可能是左侧导航） |
| `Plugin_CommandServer_Http` | 14 | **本地 HTTP 服务（SDK+MCP）** |
| `Plugin_CommandServer` | 9 | 命令通道抽象 |
| `Plugin_Splitter` | 11 | 分栏布局 |
| `Plugin_ExternalURL` | 11 | 外链打开策略 |
| `Plugin_ExtTemplate` | 7 | 外部模板 |
| `Plugin_SMIME` | 6 | S/MIME 菜单与校验 |
| `Plugin_CIM` | 2 | CIM（Coremail IM）专有实现 |
| `Plugin_Monitor` | 3 | 监控/健康 |

**推断**：这是编译期静态注册的"插件"机制（不是动态加载 dylib），用统一接口把功能挂到主框架的菜单/工具栏/状态栏上。`Plugin_CommandServer` 的存在说明"本地命令服务"被抽象为一个插件，HTTP 只是其中一种传输。
